# 框架更新机制

本机制用于管理 `references/` 的结构、规则、流程、模板和治理文档更新，确保可追溯、可回滚、可执行。

## 一、适用范围

以下变更必须走本机制：
- 新增或调整流程（如阶段拆分、门槛变化、复盘机制变化）
- 新增或调整规则（如 Rubric、风格约束、命名规范）
- 新增或调整规格文档（如语言规格、类型专项硬标准）
- 新增或调整项目结构（目录、命名、生命周期映射）
- 新增或调整模板与检查清单
- 框架入口或索引路径变化

## 二、更新原则

1. 单一真源：执行入口仅允许一个主文档，不并行维护多个同职能规范。
2. 先规范后引用：先改主文档，再改引用与项目映射。
3. 向后可追溯：保留变更记录、影响范围、迁移说明。
4. 最小破坏：优先兼容性迁移，必要时明确断点版本。

## 三、变更流程

1. 提案
- 在变更记录中新增条目（见 `框架变更记录.md` 模板字段）。
- 描述：变更目标、触发原因、涉及文档、影响范围。

2. 设计
- 明确“文档层级影响”：方法层、流程层、模板层、检查层、治理层。
- 给出“迁移路径”：旧路径 -> 新路径，是否需要批量替换。

3. 执行
- 先改主入口：`SKILL.md` 与对应层级主文档。
- 再改关联文档：模板、项目流程说明、引用索引。
- 需要删除旧文件时，必须先完成引用清理。

4. 校验
- 校验项：
	- 断链检查（旧路径是否仍被引用）
	- 入口检查（创作者入口与 Agent 入口是否一致）
	- 执行检查（标准流程与项目结构模板是否一致）

5. 记录与发布
- 在 `references/04-governance/change-log.md` 追加正式记录。
- 标注：生效日期、执行人、状态（提案/已生效/废弃）。

## 四、记录模板

每次变更至少记录以下字段：
- 变更编号（如 `FW-20260310-01`）
- 日期
- 变更类型（流程/规则/结构/模板/治理）
- 变更摘要
- 触发原因
- 影响文档
- 影响项目
- 迁移动作（新增/修改/删除）
- 校验结果
- 风险与后续动作

## 五、目录调整规则

1. 新文档归档顺序：优先放入既有层级目录；只有当文档已不属于方法、流程、模板、检查、治理或参考层时，才允许新增新的规格层。
2. 新目录命名：使用两位数字前缀保持顺序（如 `07-xxx`）。
3. 目录序号唯一：同一层级下编号不得冲突。
4. 发布目录统一：发布相关目录统一使用 `10-publication/`。
5. 质量评审目录统一：样章评审、章节质检、整书评审、终稿评审、表达精修资产统一放入 `11-quality/`。
6. 项目入口统一：项目根目录入口文件统一为 `README.md`。
7. 删除目录前提：无有效引用，且在变更记录中标注替代入口。

## 六、回滚规则

1. 如变更导致执行中断，回滚到上一个可用入口版本。
2. 回滚也必须记录：回滚原因、回滚范围、后续修复计划。
3. 回滚后 24 小时内必须补充根因分析。
