# 项目治理与复盘机制

## 治理目标

- 保证创作资产结构统一。
- 保证规则执行可检查、可追踪。
- 保证反馈驱动的持续迭代。

## 统一项目目录规范

每个项目根目录必须包含以下入口文件与一级目录：

- `README.md`
- `00-intake/`
- `01-brief/`
- `02-research/`
- `03-foundation/`
- `04-outline/`
- `05-rules/`
- `06-analysis-research/`
- `07-writing/`
- `08-operations/`
- `09-assets/`
- `10-publication/`
- `11-quality/`
- `99-archive/`

目录治理补充：
- 一级目录使用两位数字前缀保持顺序。
- 同一项目内目录序号不得冲突。
- 发布准备目录统一使用 `10-publication/`。
- 质量评审目录统一使用 `11-quality/`。
- 项目入口文件统一为根目录 `README.md`。
- `00-intake/` 只保留原始输入，不承担立项结论文档职责。
- `01-brief/` 统一存放 `立项简报.md` 与项目边界。
- `02-research/` 统一存放原始调研材料、资料摘录与题材笔记。
- `06-analysis-research/` 统一存放已裁决、可执行的分析结论与策略文件。

## 复盘频率

- 每周：产出、问题、下周动作。
- 每月：趋势、策略、方向调整。
- 每 N 章：节奏与读者反馈校正。
- 每卷：结构完整性和商业性评估。

## 变更治理

所有重大变更必须同步：

1. 变更记录
2. 受影响文件清单
3. 规则更新
4. 后续风险与回滚说明

## 版本管理建议

- 规则文档采用 `vX.Y` 标注。
- 关键里程碑节点留快照。
- 复盘报告统一命名并按时间排序。
