# 网文创作AI辅助Workflow指南

## 概述
本文档定义了一套完整的、可周期性运转的网文创作AI辅助工作流程。从初期仅有市场分析报告和选题方向开始，逐步迭代生成故事设定、大纲、章节内容，并融入读者反馈与编辑验证，最终形成可持续的万字日更循环。

## 核心设计原则
1. **数据驱动决策**：所有创作决策基于市场数据、读者画像、内容表现分析
2. **验证前置**：关键方向（品类、主题、设定）在投入大规模创作前需通过小样本验证（如前3章测试）
3. **迭代优化**：基于持续反馈（读者评价、内容表现）动态调整后续创作策略
4. **自动化流水线**：将创作过程分解为标准化步骤，实现周期性的自动内容生成与质量检查

## 一、市场分析与选题验证流程

### 1.1 市场调研方法论
**数据源**：
- 主流网文平台实时榜单（起点中文网、晋江文学城等）
- 社交媒体话题热度（微博、小红书、B站相关讨论）
- 读者评论与评分数据

**分析维度**：
1. **品类热度排名**：统计各品类（玄幻、都市、言情等）在榜单中的占比与趋势
2. **主题风向分析**：识别近期爆款作品的共同元素（系统流、重生、职业化等）
3. **读者偏好变迁**：分析评论中高频提及的爽点类型、厌恶点

**交付物**：《网文市场趋势调研报告》
- 包含：热门品类排名、趋势解读、高潜力主题建议、风险提示

### 1.2 选题方向验证
**验证标准**：
1. **市场匹配度**：选题是否符合当前热门趋势但不过度饱和
2. **差异化潜力**：能否在同类作品中形成独特卖点
3. **可持续性**：世界观与人物设定是否支持长期连载（300章+）

**验证方法**：
1. **关键词搜索测试**：用选题核心关键词搜索，分析竞争作品数量与质量
2. **读者接受度模拟**：基于相似作品评论区，推断目标读者反应
3. **创作可行性评估**：评估AI生成该题材内容的技术可行性

## 二、故事设定与大纲构建流程

### 2.1 世界观设计原则
1. **一致性**：物理规则、社会结构、力量体系内部逻辑自洽
2. **扩展性**：留出世界观升级空间（如系统功能解锁、地图扩展）
3. **代入感**：基于现实认知构建，降低读者理解门槛
4. **架空处理**：避免现实地名、机构名，使用虚构设定

### 2.2 人物设计模式
**主角设计**：
- **核心驱动力**：明确、强烈、可持续的动机（复仇、变强、解密等）
- **能力体系**：与世界观匹配且有成长空间
- **性格弧光**：设计成长轨迹（如从理性压抑到情感释放）

**配角网络**：
- **功能定位**：每个配角承担特定叙事功能（导师、对手、盟友等）
- **关系张力**：设计人物间的利益冲突、情感纠葛
- **成长性**：配角也应随剧情发展产生变化

### 2.3 分卷大纲规划
**结构模板**：
```
第一卷：启程与奠基（30-50章）
  - 核心冲突：引入
  - 主角成长：能力觉醒与初步掌握
  - 世界观揭示：逐步展开
  - 情感基点：建立读者情感连接

第二卷：发展与对抗（50-80章）
  - 冲突升级：引入更强对手/更大危机
  - 能力深化：系统功能扩展、技能组合
  - 关系复杂化：盟友变对手、对手变盟友
  - 情感深化：主角内心冲突展现

第三卷：高潮与转折（80-120章）
  - 终极对抗：解决核心冲突
  - 能力巅峰：展示系统全部潜力
  - 世界观完整：揭示所有设定谜团
  - 情感释放：主角完成性格弧光
```

**章节级规划**：
- 每章需明确：核心事件、人物出场、系统展示、爽点类型、结尾钩子
- 章节间需保证：情节连贯性、节奏变化（张弛有度）、信息量控制

## 三、内容生成与验证流程

### 3.1 前3章验证循环
**目的**：在实际投入日常更新前，验证选题、设定、文风的读者接受度

**流程**：
1. 基于选定方向生成完整的前3章内容
2. 分析生成内容与市场定位的匹配度
3. 如有多个竞争方向，并行生成3个方向的前3章供对比选择

**验证标准**：
1. **专业度适配**：专业内容密度是否适合目标读者（可通过后续读者画像分析调整）
2. **节奏把控**：前三章是否完成基础世界观引入、主角动机建立、首个冲突解决
3. **爽点分布**：是否在前三章内提供足够吸引力（至少1个智力碾压爽点）

### 3.2 读者画像分析
**分析时机**：前3章生成后，日常更新开始前

**分析维度**：
1. **人口统计**：推测目标读者年龄、性别、职业分布
2. **阅读偏好**：基于同类作品评论分析爽点类型偏好、节奏接受度
3. **消费习惯**：追更频率、付费意愿、互动参与度

**交付物**：《读者画像分析报告》
- 用于指导后续章节的：专业度调整、爽点分布、互动设计

### 3.3 日常章节生成规范
**生成频率**：
- 工作日：每日1章，固定时段生成（如17:00）
- 周末：每日1-2章，可分上午/下午两个时段

**字数标准**：
- 单章：3500-4500字（允许±10%浮动以保持情节完整）
- 项目覆盖：主线史诗/大长篇可按项目规则提升到 5500-6500 字，且可要求单章单文件存储
- 每日总字数：工作日3500-4500字，周末7000-9000字

**内容质量标准**：
1. **情节一致性**：严格遵循分卷大纲规划，不偏离主线
2. **人物一致性**：性格、动机、能力表现前后统一
3. **专业细节**：引用真实理论需基本准确，复杂概念用通俗比喻解释
4. **爽点密度**：每10章需包含：智力碾压3-4次，系统功能展示2-3次，世界观线索1-2条，情感释放点1次

**格式规范**：
- 章节内部使用数字标注小节（如`## 1`、`## 2`）
- 禁止使用hr分割线（`---`）
- 章节标题格式：`第X章`（X为阿拉伯数字）

### 3.4 自动质量检查流程
**情节连贯性检查**：
- 与前章情节衔接是否自然
- 人物行为是否符合既定性格
- 系统设定是否前后一致

**逻辑验证**：
- 智力碾压情节的逻辑严谨性
- 专业理论的正确性与通俗化处理
- 职场场景的真实性与可信度

**文风维护**：
- 保持硬核系统流特色（社会工程学、心理学应用）
- 控制物理战斗占比（<20%）
- 维持高信息密度与专业细节的平衡

### 4.2 文件命名规范
- **调研报告**：`《网文市场趋势调研报告》.md`
- **设定文档**：`世界观与人物设定.md`、`分卷大纲规划.md`
- **章节内容**：`第X章.md`（X为阿拉伯数字）
- **分析报告**：`读者画像分析报告.md`
- **反馈文件**：按“章节范围_反馈类型_日期”格式，如`第1-7章反馈汇总_20260304.md`

### 4.3 版本管理与迭代
1. **设定文档**：重大设定变更时创建新版本（如`世界观与人物设定_v2.md`）
2. **章节内容**：已发布章节不再修改，错误修正通过后续章节解释或番外篇处理
3. **工作流文档**：本文档随项目经验积累持续更新版本

### 4.4 反馈文件目录结构（新增）
**设计原则**：
- **分离存储**：将反馈与核心创作文件分离，便于管理但不干扰主线资产
- **分类归档**：按反馈来源（读者/编辑/市场）分类存储
- **版本关联**：反馈文件与对应章节范围明确关联

**目录详解**：
- `feedback/读者反馈/`：存储读者评论、本章说、书评区反馈的汇总分析
- `feedback/编辑审稿/`：存储编辑或审稿人的结构化修改意见
- `feedback/市场反馈/`：存储市场表现数据、竞品分析、趋势变化反馈

## 五、周期性运转机制

### 5.1 日常生成循环
**触发条件**：每日固定时间自动执行

**执行步骤**：
1. 读取当前进度：最近章节号、分卷大纲对应章节概要
2. 基于大纲生成下一章内容
3. 执行自动质量检查（情节连贯性、逻辑验证、文风维护）
4. 如有问题则自动润色修正
5. 保存到对应目录，更新进度记录

**异常处理**：
- 如生成内容严重偏离大纲，需人工介入调整
- 如连续多章读者反馈负面，启动紧急复盘流程

### 5.2 每周复盘流程
**复盘时间**：每周日固定时段

**复盘内容**：
1. **内容表现分析**：
   - 章节完成度：字数目标达成率
   - 质量评估：基于自动检查结果的问题统计
2. **读者反馈收集**（如有）：
   - 本章说/书评区关键词提取
   - 读者满意度变化趋势
3. **策略调整决策**：
   - 爽点分布是否需要优化
   - 专业度是否需要调整
   - 节奏控制是否需要改变

**交付物**：《第X周内容复盘报告》
- 包含：数据表现、问题诊断、调整建议

### 5.3 每月深度分析
**分析时间**：每月末

**分析维度**：
1. **长期趋势**：读者偏好变化、市场风向迁移
2. **作品竞争力**：与同期作品的差异化程度
3. **可持续性评估**：世界观与人物设定的长期支持能力

**决策输出**：
- 是否需要进行中期方向调整
- 是否需要启动新方向探索（如新增支线、番外篇）

### 5.4 按章节数触发的分析流程（新增）
**设计目的**：除了时间周期（每周/每月）的分析外，基于内容创作进度（章节数）触发深度分析，确保在关键剧情节点进行策略评估。

**触发条件**：
1. **每生成7章**：对应网文常见的"一周更新量"，分析短期读者反应与情节节奏
2. **每生成30章**：对应网文常见的"一卷篇幅"，分析卷内结构完整性与卷间过渡

**7章分析流程**：
1. **数据准备**：
   - 收集最近7章的：字数统计、自动检查问题数、读者评论（如有）
   - 提取7章内的：爽点分布、专业概念引入数、情感释放点
2. **分析维度**：
   - **节奏评估**：7章内是否形成完整的小剧情弧（引入-发展-解决）
   - **爽点密度**：是否符合每10章3-4次智力碾压的标准（折算到7章）
   - **读者反馈趋势**：评论情感倾向变化（如从积极转向负面）
3. **调整决策**：
   - **微调**：如爽点不足，在接下来3章内增加1个智力碾压情节
   - **中调**：如节奏拖沓，压缩接下来2章的信息量，加快推进
   - **报告输出**：《第X-X+6章阶段分析报告》

**30章分析流程**：
1. **数据准备**：
   - 整理整卷（30章）的：核心冲突解决进度、人物关系变化图、世界观揭示程度
   - 收集卷内所有读者反馈的聚类分析
   - 对比卷初设定的目标完成度
2. **分析维度**：
   - **结构完整性**：本卷是否完成预设的叙事功能（如"启程与奠基"）
   - **人物弧光**：主角性格发展是否符合预期轨迹
   - **世界观展开**：设定揭示节奏是否适中（不过早剧透，不过迟模糊）
   - **市场竞争力**：本卷结束时，作品在同品类中的差异化优势
3. **重大决策**：
   - **方向确认**：是否延续当前创作方向进入下一卷
   - **设定调整**：是否需要修正力量体系、社会结构等核心设定
   - **节奏重构**：下一卷是否需改变更新策略（如从日更转为更注重质量）
   - **报告输出**：《第X卷（第A-B章）完结分析报告》

**执行机制**：
- **自动检测**：系统在每章生成后检查累计章节数，若满足7或30的倍数，则触发相应分析流程
- **人工介入**：分析报告生成后，需PMO Agent或用户确认调整建议，再应用于后续创作
- **经验沉淀**：分析结论纳入`memory/spec.txt`，更新创作规范

## 六、反馈融入机制

### 6.1 初期反馈（前3章后）
- **来源**：基于同类作品读者评论的推断分析
- **应用**：形成《读者画像分析报告》，指导后续章节生成规范

### 6.2 中期反馈（日常更新中）
- **来源**：实际读者评论（如有）、内容表现数据
- **应用**：通过每周复盘动态调整创作策略

### 6.3 后期反馈（长期连载）
- **来源**：累计读者评价、编辑反馈、市场表现
- **应用**：
  1. 优化后续章节的创作方向
  2. 为下一部作品积累经验数据
  3. 更新本文档的实践方法论

### 6.4 结构化反馈处理流程（新增）
**步骤1：反馈收集与分类**
- 自动抓取：平台评论、社交媒体提及
- 人工录入：编辑意见、作者自检
- 按类型分类：情节、人物、文风、专业度、节奏

**步骤2：反馈分析与优先级排序**
- **紧急度**：影响后续剧情连贯性、人物设定崩坏
- **普遍性**：多个读者反映的共性问题
- **改正成本**：修改所需工作量与对已发布内容的影响

**步骤3：调整方案生成**
- **立即执行**：影响后续章节的紧急问题
- **分批优化**：需在多章内逐步调整的问题
- **记录待议**：需用户决策的重大方向问题

**步骤4：反馈闭环验证**
- 修改后章节的读者反馈对比
- 问题解决率统计
- 反馈处理效率评估

## 七、AI Agent执行参考

### 7.1 角色分工
- **PMO Agent**：项目规划、进度管理、质量验收、策略调整
- **Worker Agent**：具体内容生成、数据分析、质量检查

### 7.2 关键决策点
1. **方向选择**：基于市场调研数据，与用户确认最终创作方向
2. **设定验证**：前3章生成后，评估设定可行性
3. **节奏调整**：每周复盘后，调整后续创作策略
4. **中期转向**：每月深度分析后，决定是否进行方向调整
5. **章节节点分析**：每7章/30章触发的内容质量评估与策略调整

### 7.3 异常处理预案
1. **内容质量下降**：启动紧急润色流程，人工介入修正
2. **读者负面反馈激增**：暂停更新，进行深度复盘，制定调整方案
3. **技术生成问题**：切换生成策略，调整提示词设计

## 八、成功指标与评估

### 8.1 过程指标
1. **更新稳定性**：日更达成率（目标：≥95%）
2. **字数达标率**：单章字数在目标范围内的比例（目标：≥90%）
3. **质量检查通过率**：自动检查无严重问题的比例（目标：≥85%）
4. **反馈响应及时性**：从反馈收集到调整方案生成的时间（目标：≤48小时）

### 8.2 结果指标（如有数据）
1. **读者互动率**：评论/阅读比
2. **内容传播度**：分享/推荐数据
3. **市场竞争力**：与同类作品的差异化评分
