# 模板_Editor汇总与改稿指令

## 使用说明

- 由 Editor 在每轮评审后输出。
- 必须先汇总 Reviewer 与 Reader 的输入，再下发 Writer 改稿指令。
- 每条结论必须给出信息来源引用（文档路径 + 章节/条目）。
- 适用于单章、分卷、整书终稿和发布资产包四种粒度。

## Editor汇总单

```markdown

- 轮次：第___轮
- 覆盖范围：第___章-第___章 / 第___卷 / 整书终稿 / 发布资产包 / 设定版本___ / 大纲版本___
- 汇总时间：YYYY-MM-DD

## A. 输入来源（必须完整填写）
1. Reviewer评审单：
   - 文件：
   - 关键结论：

   - 文件3：
3. Writer改动说明（如有）：
   - 文件：

## B. 共识与冲突
### 1) 共识问题（多来源一致）
- 问题：
- 影响：
- 信息来源：
  - [来源1] 路径 + 条目/段落
  - [来源2] 路径 + 条目/段落

### 2) 冲突问题（来源意见不一致）
- 冲突点：
- 裁决原则：
- 裁决结论：
- 信息来源：
  - [来源1] 路径 + 条目/段落
  - [来源2] 路径 + 条目/段落

## C. 改稿优先级（P0/P1/P2）

## D. 联动更新要求（如触发）
- [ ] 已要求 Writer 执行 `模板_联动更新清单`
- 触发原因：章节新增 / 大纲改动 / 设定改动 / 正文级精修 / 整书级评审 / 发布准备
- 信息来源：
  - [来源] 路径 + 条目/段落

## E. 验收结论
- 本轮结论：通过 / 有条件通过 / 需重改 / 停止正文大修，转入发布准备
- 下轮入口：继续创作 / 回到改稿 / 回到设定 / 进入整书精修 / 进入终稿评审 / 进入发布准备

  - [来源1] 路径 + 条目/段落
  - [来源2] 路径 + 条目/段落

## F. 停改与收口判断（整书终稿 / 发布阶段必填）
- 当前问题层级：结构 / 章节 / 句面 / 校样 / 发布口径
- 是否仍需正文级改稿：是 / 否
- 若否，进入发布阶段允许动作：
  - 校样
  - 分段与版面适配
  - 文本载体口径统一
  - 发布文案整理
- 若是，必须回改章节：
  1.
  2.
```

## 来源引用规范（强制）

每条关键结论至少引用 1 个来源；P0 项至少引用 2 个来源（Reviewer + Reader 各至少 1 条）。

推荐写法：
- `08-operations/feedback/Reader反馈_第12章_角色A.md#“节奏评价”`
- `11-quality/章节质检_第12章.md#“情节一致性”`
- `08-operations/change-log/变更记录_20260310.md#“第12章改动”`
