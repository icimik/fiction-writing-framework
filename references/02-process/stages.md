# 标准创作流程

说明：本文件是执行层唯一流程入口。`SKILL.md` 只保留入口、原则与导航；阶段细则、停改规则、终稿与发布流程以本文件为准。方法细化原则使用 `references/01-domain/` 各分册；中文生成硬规格查 `references/01-domain/language/`。

## 运行契约

角色分工：
- Writer：负责创作与改稿落地。
- Editor：负责编辑审阅、反馈汇总、改稿指令、停改裁决与阶段验收。
- Reviewer：负责规则化评审与质量打分。
- Reader：负责多读者画像反馈，包括单章体验、整书连读体验与渠道感知。

协作扩展：
- 角色交接、按阶段协作粒度、交接产物细则，见 `references/02-process/collaboration.md`。

执行硬规则：
- 生成任何中文正文前，必须已读 `references/01-domain/language/中文生成约束.md`，并在生成过程中执行其三阶段检查（生成前、生成中、生成后）。不可以"事后精修会处理"为由跳过。
- 单次只允许变更一个对象：章节 / 大纲 / 设定（三选一）。
- 当任务切换为整书中文表达精修时，单个章节视为当前唯一对象，逐章推进。
- 当任务切换为整书终稿评审或发布准备时，整书终稿或发布资产包视为当前唯一对象。
- 单章节改写必须整章重写，不得以查找替换或末尾追加代替。
- 用户要求逐字逐句精修时，只允许重写句面，不得偷换结构、因果、人物关系与章尾钩子。
- 禁止创建 `.bak` 或同类正文副本。
- 每次生成后必须完成字数、格式、风格、视角、节奏、编码检查。
- 不用评论腔、议论文腔、概念化总结句代替小说句。
- 发布准备默认不重开结构性改稿。

运行模式：
- 通用创作模式：短中长篇、非日更、样章或全稿改写。
- 网文连载模式：日更/周更、市场验证与反馈循环强约束。
- 短篇小说集模式：多篇共享世界观、强调横向统一与纵向差异。

必填输入：
- 类型与题材
- 目标体量（字数或章数）
- 目标读者
- 创作目标（新建/续写/重写/审阅）
- 运行模式（通用创作/网文连载/短篇小说集）

缺省策略：
- 未给运行模式：默认通用创作。
- 未给章数：默认先交付"10 章节拍 + 1 章样章"。
- 未给风格：默认"清晰、叙事优先、展示驱动"。
- 未给创作目标：默认"新建"。
- 未给类型与题材：根据一句话设定关键词自动归类；若无法判定，默认"都市异能"。
- 未给目标读者：默认"18-35 岁网文读者，偏剧情驱动"。

单句启动兜底（仅提供一句话设定时）：
- 平台：默认"待定（按通用创作标准输出，可后置适配）"。
- 更新节奏：默认"每周 3 更"。
- 目标体量：默认"长篇，预计 120 章"。
- 禁用项：默认"无现实敏感映射、无超出设定边界的能力跳变"。

最小交付（MVP）：
- 一页式世界观（规则、限制、验证场景）
- 三角色卡（主角/对手/关键配角）+ 关系矩阵
- 10 章节拍大纲（每章推进目标 + 结尾钩子）
- 1 章样章（含自检要点）

## 标准执行链

1. 阶段 0：立项输入
2. 导入融合前置流程
3. 阶段 1：设定完善
4. 阶段 2：分析与规划
5. 阶段 3：样章验证
6. 阶段 4：反馈迭代
7. 阶段 5：持续生产
8. 阶段 6：周期复盘
9. 阶段 7：整书审读与中文表达精修
10. 阶段 7b：中文重塑（条件触发，非必经）
11. 阶段 8：终稿级多方评审与发布裁决
12. 阶段 9：发布准备 / 校样准备
13. 阶段 10：结项复盘与框架反哺

长篇项目补充要求：
- 阶段 7 不是普通语病修正，而是整书级表达系统校正。默认使用重述法，禁止在原文上反复重试。
- 阶段 7b 仅在阶段 7 完成后仍有超过 30% 章节存在系统性翻译腔时触发，需用户明确授权。
- 阶段 8 默认以整书为对象，不再只看单章局部好坏。
- 阶段 9 默认不重开结构性改稿，只处理发布口径、校样和载体适配。
- 阶段 10 必须把本项目新形成的流程资产和规则资产回写框架。

## 阶段 0：立项输入

输入：idea 或基础设定文档。
输出：
- `00-intake/` 中保留 idea、原始设定与外部输入
- `01-brief/立项简报.md`

必填项：
- 类型与题材
- 目标读者
- 平台与更新节奏
- 目标体量
- 风格边界与禁用项

验证门槛：
- 是否能用一句话说明"主角-冲突-目标-代价"。
- 是否明确平台与更新约束。

→ 必用分册：`references/01-domain/genre.md`

网文连载附加动作：
- 先完成市场调研并形成《市场与竞品分析》初稿。
- 进行选题可行性验证：市场匹配度、差异化潜力、300+章可持续性。

短篇小说集附加动作：
- 明确是"单作者短篇集 / 设定集驱动短篇集 / 同世界观导入整编集"中的哪一种。
- 先定义短篇集统一内核：主题母题、制度母题、地区差异、篇幅带宽、篇章转正标准。

## 导入融合前置流程

适用：
- 存在外部创作空间的同世界观设定、短篇、长篇蓝图或历史稿。
- 需要在不打散核心设定的前提下，将外部资产并入当前项目。

输入：
- 外部导入文档、正文、设定、蓝图、时间线说明。

输出：
- `06-analysis-research/导入资产融合评估_*.md`
- `08-operations/feedback/导入融合审阅_*.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

建议模板：
- `references/03-resources/templates/模板_导入资产融合评估.md`

执行步骤：
1. 以批次归档导入源：存入 `99-archive/import-YYYYMMDD/`。禁止直接把导入稿放进正式章节目录。
2. 建立资产清单：设定、人物、阵营、时间线节点、已完稿短篇、蓝图/未写提纲。
3. 做一致性体检：核心设定、时间线、命名规则、阵营职能、世界规则边界是否冲突。
4. 对每项资产给出处理结论：保留 / 改写并并入 / 拆分吸收 / 仅归档不转正。
5. 统一落库：设定并入 `03-foundation/`，大纲并入 `04-outline/`，转正短篇并入 `07-writing/chapters/`，未转正稿保留在归档层或 `07-writing/samples/`。
6. 联动更新：角色、世界观、阵营、时间线、规则手册、日志与变更记录。

强制约束：
- 导入融合阶段优先级高于正文续写；未完成融合评估，不得将导入资产视为正式 canon。
- 若导入内容与当前项目冲突，优先保全当前项目核心设定。
- 导入融合允许整篇重写、角色替换、地区迁移、时间位置调整，但必须登记理由与影响范围。

## 阶段 1：设定完善

输入：立项简报。
输出：
- `03-foundation/世界观设定.md`
- `03-foundation/角色设定.md`
- `03-foundation/阵营设定.md`
- `05-rules/创作规则手册.md`
- 强风格约束项目补充：`STYLEGUIDE.md`、`03-foundation/souls/*.SOUL.md`、`09-assets/项目写作语言参考_*.md`

执行要点：
- 能力体系必须写明限制、代价、弱点。
- 命名与映射规则必须先行。
- 设定文档需给出"开放问题"与后续回收计划。
- `STYLEGUIDE.md`、`SOUL.md` 与项目写作语言参考只允许从设定、角色弧线、分卷结构、题材与体裁形式推导，不得从现有正文惯性写法反推。
- 长篇、连载、多 POV 或用户对语言/人设稳定性有强要求的项目，必须在样章前补建项目级 `STYLEGUIDE.md`。
- 三个及以上会持续复用的主要角色，必须在样章前建立对应 `SOUL.md`。
- 若项目存在中文表达风险，必须优先参照 `references/01-domain/language/00.index.md` 及相关分册，再压缩成短引用的项目写作参考。
- 若项目已有较多正文后才补建这些文档，必须先写明用途边界：继续生成的长期控制基线，或发布阶段的分析与最小修正基线。
- 若为短篇小说集，必须额外写明：地区命名规则、时间线排序基准、篇章转正标准、跨篇角色复用规则。

→ 必用分册：`references/01-domain/worldbuilding.md`、`references/01-domain/character.md`

建议模板：
- `references/03-resources/templates/模板_STYLEGUIDE.md`
- `references/03-resources/templates/模板_SOUL.md`
- `references/03-resources/templates/模板_项目写作语言参考.md`

## 阶段 2：分析与规划

输入：基础设定。
输出：
- `02-research/` 中沉淀原始调研材料
- `06-analysis-research/读者画像分析.md`
- `06-analysis-research/市场与竞品分析.md`
- `04-outline/分卷大纲.md`
- `04-outline/前三章节拍.md`

执行要点：
- `02-research/` 只放原始研究材料。
- `06-analysis-research/` 只放已裁决、可执行的分析结论。
- 先做读者画像，再定爽点/信息密度分布。
- 分卷大纲需包含：卷目标、小高潮、灵魂黑夜、卷末钩子。
- 前三章节拍必须覆盖：世界观入口、主角动机、首个冲突闭环。
- 新项目必须由 Editor + Writer 联合完成选题分析。
- 若为短篇小说集，必须额外产出短篇矩阵、横向差异化检查、转正顺序与篇幅带宽规划。

→ 必用分册：`references/01-domain/plot.md`、`references/01-domain/narrative.md`

## 阶段 3：样章验证

输入：分卷与节拍。
输出：
- `07-writing/samples/第1-3章.md`
- Reviewer / Reader / Editor 三方审阅文档
- `11-quality/样章评审_*.md`

执行要点：
- 前三章必须完成：世界观入口、主角动机、首个冲突闭环。
- 样章阶段必须完成 Reviewer + Reader + Editor 三方审阅。
- 生成前必读：`references/01-domain/language/中文生成约束.md`、项目 `STYLEGUIDE.md` / `SOUL.md`。
- 样章被采纳时二选一：直接转正（移至 `chapters/`）或改写转正（原稿归档到 `99-archive/samples-YYYYMMDD/`）。
- 转正或归档动作必须同步更新变更记录与工作日志。

→ 必用分册：`references/01-domain/rhetoric.md`、`references/01-domain/editing-review.md`

## 阶段 4：反馈迭代

输入：作者/编辑/读者反馈。
输出：
- `08-operations/feedback/章节反馈_*.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

执行要点：
- 反馈按情节/角色/设定/节奏/文风分类。
- 每条调整标注"立即执行/延后执行/不采纳"。
- 需形成"问题-原因-动作-验证"闭环。
- Editor 必须汇总并输出改稿优先级（P0/P1/P2）。
- Reader 反馈必须基于至少 3 个角色卡执行。
- 若为短篇小说集，Editor 必须额外输出：单篇合规问题、整组雷同问题、转正/回退/归档建议。

## 阶段 5：持续生产

输入：修订后的大纲与规则。
输出：
- `07-writing/chapters/第X章.md`
- `11-quality/章节质检_第X章.md`
- `08-operations/logs/工作日志_*.md`

执行要点：
- 每章完成后至少更新一次工作日志。
- 每 5-10 章检查一次伏笔台账与主线推进比例。
- 单章目标字数：3500-4500（可浮动 ±10%）。项目规则可覆盖默认值。
- 章节格式：长篇使用 `第X章`；短篇集允许 `地区·篇名` 格式，须在项目规则中统一。
- 若本轮有改动，必须同步联动更新（使用 `references/03-resources/templates/模板_联动更新清单.md`）。
- 章节改写必须整章重写，不得做局部替换式修补。
- 生成完成后必须执行编码检查。

生成前必读：`references/01-domain/language/中文生成约束.md`、项目 `STYLEGUIDE.md` / `SOUL.md`。

初稿写作操作要点（心流与停泊）：
- 前期准备（5 分钟）：翻看本章大纲、人设、核心冲突、章末钩子。
- 开篇切入：直接进动作/对话场景，前 3 行抓眼球。
- 正文推进：按"冲突升级 → 角色交锋 → 情绪爆发"推进，对话驱动。
- 收尾断章：落实章末钩子，执行停泊法则——留半段内容次日写。
- 卡文急救：卡情节把主角逼入绝境；卡对话启用苏格拉底式交锋；卡节奏加入小冲突；卡文笔先大白话写完。

## 阶段 6：周期复盘

输出：
- `08-operations/retrospectives/周复盘_*.md`
- `08-operations/retrospectives/月复盘_*.md`
- `08-operations/retrospectives/N章复盘_*.md`
- `08-operations/retrospectives/分卷复盘_*.md`

执行要点：
- 周复盘看执行稳定性。
- 月复盘看策略方向。
- N 章复盘看节奏偏移。
- 分卷复盘看结构完整性与商业性。
- 由 Editor 与 Writer 协同主持。

## 阶段 7：整书审读与中文表达精修

适用：全书结构已稳定，语言层仍存在翻译腔、英语痕迹、中文表达不顺等问题。

输入：完整正文、既有大纲与设定、整书评审资产。

输出：
- `11-quality/整书中文表达逐章审读提要_*.md`
- `11-quality/整书逐章详细内容总结_*.md`
- 分批精修后的 `07-writing/chapters/第X章.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

执行原则：
- 只改表达，不改结构。
- 保留既有节奏、章尾钩子、因果链和信息释放顺序。
- 先整书读清，再逐章下刀。
- 生成前必读：`STYLEGUIDE.md`、`SOUL.md`、项目写作语言参考、大纲与最近一轮评审裁决。

标准动作：
1. 先做逐章审读提要。
2. 对高风险长篇补逐章详细内容总结。
3. 按批次执行整章表达重述（默认方法）。
4. 对高风险章节执行分层精修。
5. 做整书回读与口径复核。
6. 联动发布资产。

操作禁令：
- 禁止"给 LLM 原文让它改"超过一轮。
- 禁止"通读全章逐句润色"。
- 禁止在精修中引入原文没有的信息。

→ 方法细则：`references/01-domain/editing-review.md`
→ 反模式清单：`references/01-domain/language/中文生成约束.md`

重点清理项：
- 压缩名词式说法、罗列型断句、不自然口语、翻译腔比喻。
- 解释腔、分析腔、概念先行句、判词句、对照句、元叙事残留。
- 写得太满、太圆、太会说明自己的收束句。

文本载体细则：
- 短信、聊天、系统提示保留载体感。
- 便签、药盒说明等短文本按物理载体习惯处理。
- 标点位置服从中文排版常识。

## 阶段 7b：中文重塑

适用：全书已经过阶段 7，但整体仍存在系统性翻译腔。本阶段是完全独立的重建流程，不是阶段 7 的续集。

与阶段 7 的根本区别：
- 阶段 7 是"在现有文本上精修"——输入是原文。
- 阶段 7b 是"从叙事任务重建"——输入是叙事任务清单，原文只用于提取和事后比对。

入口条件（必须全部满足）：
1. 已完成阶段 7 或等效精修流程。
2. 精修后仍有超过 30% 的章节存在系统性翻译腔。
3. 用户明确授权进入重塑流程。

标准动作：
1. 提取逐章叙事任务清单。叙事任务必须用具体事件描述，禁止抽象概括。
2. 逐章从叙事任务重建：只给叙事任务清单 + 锚文本 + STYLEGUIDE/SOUL 约束，不给原文。
3. 对白单独一轮：按角色 SOUL 和当下情境状态重写。
4. 删减轮：只做减法。
5. 整书回读：标记不自然段落，仅用重述法修复。
6. 联动更新：同步发布文案、手记、后记、变更记录和工作日志。

操作禁令：
- 禁止在重建时参考原文的句式和句法结构。
- 禁止对重建稿执行"通读逐句润色"。
- 禁止在一轮重建中同时处理叙述和对白。

质量验证：
- 重建稿必须通过 `references/01-domain/language/中文生成约束.md` 第 8 节快速自检 8 问。
- 逐章比对叙事任务清单，确认无信息遗漏。
- 整书回读时翻译腔章节比例必须低于 10%。

→ 方法细则：`references/01-domain/editing-review.md`

## 阶段 8：终稿级多方评审与发布裁决

适用：正文已完成整书级生产与主要精修。

输入：终稿正文、阶段 7 精修资产、既有整书评审资产。

执行要求：
- Reviewer 以整书为单位评审。
- Reader 至少 3 份，必须补充整书连读感受、章节间口径一致性、弃读风险位置与传播感知。
- Editor 必须给出裁决：继续精修 / 通过 / 停止正文大修转入发布准备。

裁决规则：
- 若存在 P0 或 P1，继续正文改稿。
- 若剩余问题主要是措辞、校样、发布口径，则停止正文大修，转入阶段 9。

## 阶段 9：发布准备 / 校样准备

适用：终稿裁决通过后。

执行边界：
- 不重开结构性改稿。
- 不补新事件改变人物命运。
- 只做发布口径统一、载体适配、版心适配、分段优化、异常标点修正、平台文案整理。

发布资产要求：
- 对外书名、平台标签、简介版本必须统一。
- 推荐文案、手记、后记必须服从正文终稿气质。
- 正文停改后，发布资产必须视为统一资产包做口径对齐。
- 默认从现有资产拷定，不临场重写。

建议模板：
- `references/03-resources/templates/模板_发布前最终核对单.md`
- `references/03-resources/templates/模板_发布前最终核验.md`

## 阶段 10：结项复盘与框架反哺

执行要点：
- 提炼本项目高频问题、新增流程节点、新形成的硬规则、可复用的方法与停改判断线。
- 框架反哺必须写回框架文档，不只留在项目日志里。
- 若项目验证出新边界或新链路，必须优先回写流程、模板和检查清单。

## 正文停改与发布收口规则

进入"停止正文大修，转入发布收口"的条件：
1. 整书主线、人物关系、因果链、卷尾接力已经稳定。
2. 整书终稿评审不存在 P0 / P1。
3. 剩余问题主要落在说明密度、措辞口径、排版校样、发布文案统一。
4. Editor 明确给出"通过"或"可进入发布准备收口阶段"的结论。

进入发布状态后允许做的事：轻量校样、长段分段适配、文本载体口径统一、发布页简介与社交文案整理、手记后记附言整理。

进入发布状态后默认不做的事：不重开结构性改稿、不补事件、不把正文重新拉回逐章大修。

若确有例外，必须满足：有明确 P0/P1 证据、能指出具体章节与问题、Editor 重新裁定。

## 既有项目接入模式

执行步骤：
1. 按 `references/02-process/project-structure.md` 重组目录与资产。
2. 将既有设定归档到 `03-foundation/`，既有正文归档到 `07-writing/chapters/`。
3. 由 Reviewer 先做基线体检，Editor 生成修复清单。
4. Writer 按修复清单完成首轮改稿，再进入标准阶段 4-10 循环。

## 同世界观导入整编模式

执行步骤：
1. 新建导入批次目录：`99-archive/import-YYYYMMDD/`
2. 完成 `导入资产融合评估_*.md`
3. 逐项裁决导入资产的 canon 状态与处理动作
4. 先更新 foundation / outline / rules，再处理正文
5. 对受影响篇章执行基线复审与反雷同复审
6. 记录批次影响范围与后续待改篇目

## 周期机制

日常循环（每日触发）：
1. 读取当前进度与对应章节节拍。
2. 生成下一章。
3. 执行自动质检。
4. 问题修正后落盘并更新日志。

每周复盘：检查更新达成率、字数达标率、质检问题分布。
每月复盘：分析读者偏好与市场风向变化、评估差异化与可持续性、决策方向调整。
章节数触发复盘：每 7 章看短弧完成度，每 30 章看分卷完整性，整书完成后强制进入阶段 7 和阶段 8。

## 质量门槛（Rubric）

评分维度（5 分制）：
1. 规则一致性
2. 角色驱动性
3. 情节因果性
4. 叙事有效性
5. 语言可读性

建议阈值：
- 通用创作：平均分 > 4.1
- 网文连载：平均分 > 4.1，且章节钩子强度 > 4.3
- 终稿发布判断：无 P0/P1，且 Editor 裁决通过后方可进入阶段 9

## 反馈闭环（结构化处理）

1. 收集与分类：按情节/人物/文风/专业度/节奏归档。
2. 优先级排序：按紧急度、普遍性、改动成本排序。
3. 生成调整方案：标注立即执行、分批优化、待决策项。
4. 验证与沉淀：对比调整前后反馈，更新规则与清单。
5. 整书结项后：将新增流程与规则回写框架。

## 异常处理

1. 连续偏离大纲：暂停生成，先回到分卷目标重建节拍。
2. 读者负反馈激增：触发紧急复盘并压缩试错窗口。
3. 文风或质量下滑：强制执行样章级重审再恢复日更。
4. 中文表达精修中误伤结构：立即回到该章审读提要，按"叙事任务优先"回修。
5. 发布阶段出现"还想再大修正文"的冲动：先对照"正文停改与发布收口规则"裁决。
