# 工作流规则

停改规则、周期机制与异常处理。阶段定义见 `stage-details.md`，运行契约见 `stages.md`。

## 正文停改与发布收口规则

进入"停止正文大修，转入发布收口"的条件：
1. 整书主线、人物关系、因果链、卷尾接力已经稳定
2. 整书终稿评审不存在 P0 / P1
3. 剩余问题主要落在说明密度、措辞口径、排版校样、发布文案统一
4. Editor 明确给出"通过"或"可进入发布准备收口阶段"的结论

进入发布状态后允许：轻量校样、长段分段适配、文本载体口径统一、发布页简介与社交文案整理、手记后记附言整理。

进入发布状态后默认不做：不重开结构性改稿、不补事件、不把正文重新拉回逐章大修。

若确有例外，必须满足：有明确 P0/P1 证据、能指出具体章节与问题、Editor 重新裁定。

## 周期机制

日常循环（每日触发）：读取当前进度 → 生成下一章 → 执行自动质检 → 修正后落盘并更新日志。

复盘节奏：
- 每周：检查更新达成率、字数达标率、质检问题分布
- 每月：分析读者偏好与市场风向变化、评估差异化与可持续性
- 每 7 章：看短弧完成度
- 每 30 章：看分卷完整性
- 整书完成后：强制进入阶段 7 和阶段 8

## 反馈闭环

1. 收集与分类：按情节/人物/文风/专业度/节奏归档
2. 优先级排序：按紧急度、普遍性、改动成本排序
3. 生成调整方案：标注立即执行、分批优化、待决策项
4. 验证与沉淀：对比调整前后反馈，更新规则与清单
5. 整书结项后：将新增流程与规则回写框架

## 异常处理

1. 连续偏离大纲：暂停生成，先回到分卷目标重建节拍
2. 读者负反馈激增：触发紧急复盘并压缩试错窗口
3. 文风或质量下滑：强制执行样章级重审再恢复日更
4. 中文表达精修中误伤结构：立即回到该章审读提要，按"叙事任务优先"回修
5. 发布阶段出现"还想再大修正文"的冲动：先对照停改规则裁决
