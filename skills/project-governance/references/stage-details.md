# 阶段详细定义

各阶段的输入、输出、执行要点与必用分册。运行契约与执行链见 `stages.md`。

## 阶段间质量门控

阶段切换必须满足以下门控条件，不可跳过：

| 从 → 到 | 门控条件 |
|---------|---------|
| 阶段 0 → 阶段 1 | 立项简报已完成；类型、读者、体量、运行模式已明确 |
| 阶段 1 → 阶段 2 | 世界观设定、角色设定、创作规则手册已落盘；长篇已建 `STYLEGUIDE.md`；≥3 角色已建 `SOUL.md` |
| 阶段 2 → 阶段 3 | 分卷大纲、前三章节拍已落盘；结构选型已固定；伏笔台账已建立 |
| 阶段 3 → 阶段 4 | 样章三方审阅已通过；样章已转正或归档 |
| 阶段 4 → 阶段 5 | 反馈已分类归档；P0/P1 已处理；改稿指令已执行 |
| 阶段 5 → 阶段 6 | 当前批次章节已完成；工作日志已更新 |
| 阶段 6 → 阶段 7 | 复盘结论已归档；全书结构已稳定 |
| 阶段 7 → 阶段 8 | 整书精修完成；翻译腔反模式残留 ≤ 阈值 |
| 阶段 8 → 阶段 9 | 终稿评审不存在 P0/P1；Editor 裁决"通过"或"停止正文大修" |
| 阶段 9 → 阶段 10 | 发布资产已构建；发布前核验已通过 |

## 阶段 0：立项输入

输入：idea 或基础设定文档。
输出：`00-intake/` 中保留原始输入、`01-brief/立项简报.md`

必填项：类型与题材、目标读者、平台与更新节奏、目标体量、风格边界与禁用项。

验证门槛：是否能用一句话说明"主角-冲突-目标-代价"；是否明确平台与更新约束。

→ 必用分册：`narrative-knowledge` 的 references/genre.md

网文连载附加：先完成市场调研并形成《市场与竞品分析》初稿，进行选题可行性验证。
短篇小说集附加：明确集类型，定义统一内核、主题母题、篇幅带宽、篇章转正标准。

## 导入融合前置流程

适用：存在外部同世界观资产需要并入当前项目。

输入：外部导入文档、正文、设定、蓝图、时间线说明。
输出：`06-analysis-research/导入资产融合评估_*.md`、变更记录、工作日志。

建议模板：`templates` 的 references/导入/模板_导入资产融合评估.md

执行步骤：
1. 批次归档导入源到 `99-archive/import-YYYYMMDD/`，禁止直接放进正式目录
2. 建立资产清单：设定、人物、阵营、时间线节点、已完稿短篇、蓝图
3. 一致性体检：核心设定、时间线、命名规则、阵营职能、世界规则边界
4. 对每项资产给出处理结论：保留 / 改写并并入 / 拆分吸收 / 仅归档不转正
5. 统一落库并联动更新

强制约束：导入融合优先级高于正文续写；若冲突优先保全当前项目核心设定。

## 阶段 1：设定完善

输入：立项简报。
输出：`03-foundation/世界观设定.md`、`03-foundation/角色设定.md`、`05-rules/创作规则手册.md`

执行要点：
- 能力体系必须写明限制、代价、弱点
- `STYLEGUIDE.md`、`SOUL.md` 只允许从设定、角色弧线、分卷结构推导，不得从正文惯性反推
- 长篇连载项目必须在样章前补建 `STYLEGUIDE.md`
- 三个及以上持续复用的主要角色必须建立 `SOUL.md`

→ 必用分册：`narrative-knowledge` 的 references/worldbuilding.md、character.md

## 阶段 2：分析与规划

输入：基础设定。
输出：`06-analysis-research/读者画像分析.md`、`04-outline/分卷大纲.md`、`04-outline/前三章节拍.md`

执行要点：
- 先做读者画像，再定爽点/信息密度分布
- 分卷大纲需包含：卷目标、小高潮、灵魂黑夜、卷末钩子
- 前三章节拍必须覆盖：世界观入口、主角动机、首个冲突闭环

→ 必用分册：`narrative-knowledge` 的 references/plot.md、narrative.md

## 阶段 3：样章验证

输入：分卷与节拍。
输出：`07-writing/samples/第1-3章.md`、三方审阅文档、`11-quality/样章评审_*.md`

执行要点：
- 前三章必须完成：世界观入口、主角动机、首个冲突闭环
- 生成前必读：`chinese-writing-constraints` 的 references/anti-patterns.md 和 references/checking-process.md、项目 STYLEGUIDE / SOUL
- 样章被采纳时二选一：直接转正或改写转正（原稿归档）

→ 必用分册：`narrative-knowledge` 的 references/rhetoric.md、editing-review.md

## 阶段 4：反馈迭代

输入：作者/编辑/读者反馈。
输出：`08-operations/feedback/章节反馈_*.md`、变更记录、工作日志

执行要点：
- 反馈按情节/角色/设定/节奏/文风分类，每条标注"立即执行/延后执行/不采纳"
- Editor 必须输出改稿优先级（P0/P1/P2）
- Reader 反馈必须基于至少 3 个角色卡执行

## 阶段 5：持续生产

输入：修订后的大纲与规则。
输出：`07-writing/chapters/第X章.md`、`11-quality/章节质检_第X章.md`、工作日志

执行要点：
- 每章完成后至少更新一次工作日志
- 每 5-10 章检查一次伏笔台账与主线推进比例
- 单章目标字数：3500-4500（可浮动 ±10%）
- 章节改写必须整章重写，不得做局部替换式修补
- 生成前必读：`chinese-writing-constraints` 的 references/anti-patterns.md 和 references/checking-process.md

## 阶段 6：周期复盘

输出：周/月/N章/分盘复盘文档到 `08-operations/retrospectives/`

执行要点：周复盘看执行稳定性，月复盘看策略方向，N章复盘看节奏偏移，分卷复盘看结构完整性。由 Editor 与 Writer 协同主持。

## 阶段 7：整书审读与中文表达精修

适用：全书结构已稳定，语言层仍存在翻译腔等问题。

输入：完整正文、既有大纲与设定、整书评审资产。

执行原则：只改表达，不改结构。先整书读清，再逐章下刀。

标准动作：
1. 先做逐章审读提要
2. 按批次执行整章表达重述（默认方法）
3. 做整书回读与口径复核
4. 联动发布资产

操作禁令：禁止"给 LLM 原文让它改"超过一轮；禁止"通读全章逐句润色"。

→ 方法细则：`narrative-knowledge` 的 references/editing-review.md

## 阶段 7b：中文重塑

适用：阶段 7 完成后仍有超过 30% 章节存在系统性翻译腔，需用户明确授权。

与阶段 7 的根本区别：阶段 7 是"在现有文本上精修"；阶段 7b 是"从叙事任务重建"，原文只用于提取和事后比对。

标准动作：
1. 提取逐章叙事任务清单（用具体事件描述，禁止抽象概括）
2. 逐章从叙事任务重建，不给原文
3. 对白单独一轮重写
4. 删减轮：只做减法
5. 整书回读：标记不自然段落，仅用重述法修复

操作禁令：禁止参考原文句式；禁止"通读逐句润色"；禁止同时处理叙述和对白。

## 阶段 8：终稿级多方评审与发布裁决

适用：正文已完成整书级生产与主要精修。

执行要求：
- Reviewer 以整书为单位评审
- Reader 至少 3 份，补充整书连读感受、口径一致性、弃读风险位置
- Editor 给出裁决：继续精修 / 通过 / 停止正文大修转入发布准备

裁决规则：若存在 P0 或 P1 继续改稿；若剩余问题主要是措辞/校样/口径则转入阶段 9。

## 阶段 9：发布准备 / 校样准备

适用：终稿裁决通过后。

执行边界：不重开结构性改稿，不补新事件，只做发布口径统一、载体适配、版心适配、分段优化、异常标点修正、平台文案整理。

建议模板：`templates` 的 references/发布/模板_发布前最终核对单.md、模板_发布前最终核验.md

## 阶段 10：结项复盘与框架反哺

执行要点：提炼本项目高频问题、新增流程节点、新形成的硬规则。框架反哺必须写回框架文档，不只留在项目日志里。
