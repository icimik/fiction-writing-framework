# 多Agent操作流程

## 目标

定义 Writer、Editor、Reviewer、Reader 的协作职责、交接产物与迭代节奏，作为 `标准创作流程.md` 的扩展说明使用。

## 定位与优先级

- 本文件不是主流程入口。
- 主流程、阶段切换、停改规则、终稿裁决、发布准备边界，以 `project-governance 的 references/stages.md` 为准。
- 本文件只回答三类问题：
  - 各角色在不同阶段分别做什么
  - 产物交给谁、如何交接
  - 分章 / 分卷 / 整书 / 终稿 / 发布阶段如何组织协作
- 若本文件与 `标准创作流程.md` 冲突，以 `标准创作流程.md` 为准。

## 角色职责与交接

1. Writer（创作）
- 输入：Editor 改稿指令、当前大纲、规则手册、当前阶段要求。
- 输出：章节草稿/改稿稿、改动说明、必要的联动更新记录。
- 交接给 Reviewer 与 Reader。

2. Reviewer（规则评审）
- 输入：Writer 当轮稿件、`review-rubric 的 references/checklists.md`、Rulebook 分册。
- 输出：规则评审单（评分、问题清单、严重级别、证据位置）。
- 交接给 Editor。

3. Reader（读者反馈）
- 输入：Writer 当轮稿件、`templates` 的 references/审阅/模板_Reader读者角色卡.md。
- 输出：读者体验反馈单（爽点、拖沓点、代入感、弃读风险、推荐改动）。
- 交接给 Editor。

4. Editor（汇总与验收）
- 输入：Reviewer 评审单 + Reader 反馈单 + Writer 改动说明。
- 输出：
  - 汇总反馈（冲突点与共识点）
  - 改稿优先级（P0/P1/P2）
  - Writer 改稿指令
  - 验收结论（通过 / 有条件通过 / 需重改 / 停止正文大修，转入发布准备）
- 交接给 Writer 并进入下一轮。

## 标准协作循环

1. Writer 产出当轮稿件。
2. Reviewer 生成规则评审单。
3. Reader 按角色模板生成读者反馈单。
4. Editor 汇总并下发改稿指令。
5. Writer 改稿并提交联动更新记录。
6. Editor 验收通过后进入下一章节；未通过回到第4步。

说明：
- 这一循环是通用协作骨架。
- 单次只变更一个对象、整章重写、停改规则、发布边界等硬规则，不在本文件重复定义，统一服从 `标准创作流程.md`。

## 按阶段的协作粒度

1. 样章期与卷内推进期
- 默认使用“分章闭环”。
- 可以按单章或每 2-3 章一轮组织 Reviewer / Reader / Editor。

2. 分卷完成期
- 使用“分卷闭环”。
- 目标是检查卷内压力线、节奏、卷尾接力和角色弧线是否成立。

3. 整书完成期
- 使用“整书闭环”。
- Reader 反馈从单章体验切换为整书连读体验。

4. 终稿裁决期
- 使用“终稿闭环”。
- Reviewer、Reader、Editor 都必须以整书终稿为对象，而不是拆成局部碎片判断。

5. 发布准备期
- 使用“发布闭环”。
- 重点转为口径、定位、中文习惯、渠道适配和校样，不再重复剧情评判。

## 各阶段建议交接产物

1. 分章 / 分卷阶段
- Writer：章节稿或分卷修订稿
- Reviewer：评审单
- Reader：角色反馈单
- Editor：汇总与改稿指令

2. 整书中文表达精修阶段（阶段 7）
- Writer：按重述法重建的整章稿、分层精修稿
- Reviewer：高风险章节或整书语言可读性复核意见
- Reader：整书中文顺滑度、连读阻滞点、翻译腔残留反馈
- Editor：精修优先级与阶段验收

2b. 中文重塑阶段（阶段 7b，条件触发）
- Writer：从叙事任务清单重建的整章稿
- Reviewer：重建稿与叙事任务清单比对复核
- Reader：重建稿中文自然度、连读体验反馈
- Editor：重塑范围确认与阶段验收

3. 终稿裁决阶段
- Writer：终稿版正文
- Reviewer：整书终稿评审单
- Reader：至少 3 份整书终稿反馈
- Editor：终稿汇总与改稿指令、停改裁决

4. 发布准备阶段
- Writer：发布资产初稿
- Reviewer：口径与风险复核
- Reader：平台感知、传播感知、中文习惯反馈
- Editor：发布资产修订意见与收口结论

## 新项目选题协同（Editor + Writer）

1. 收集候选题材与一句话设定。
2. 评估市场匹配度（热度、竞争、题材窗口）。
3. 评估差异化（卖点、叙事钩子、角色关系优势）。
4. 评估可持续性（100+章节冲突燃料、角色成长空间、世界扩展性）。
5. 输出《选题分析与立项建议》。

## 既有项目接入协同

1. Writer 先归档与重组既有资产（设定、正文、大纲）。
2. Reviewer 执行基线体检（设定一致性、人物连续性、主线完整性）。
3. Editor 输出修复清单与改写优先级。
4. Writer 完成首轮修复后进入标准协作循环。

## 联动更新协同（Writer 执行，Editor 验收）

触发条件：当轮发生以下任一改动：
- 新增章节
- 修改大纲
- 修改设定
- 执行正文级精修
- 执行整书级评审
- 启动发布准备或校样准备

必须同步更新：
- `03-foundation/角色设定.md`（角色清单/状态）
- `03-foundation/世界观设定.md`（规则与边界）
- `03-foundation/阵营设定.md`（阵营关系与利益）
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`
- 需要时更新 `11-quality/` 与 `10-publication/` 对应资产

验收标准：
- Editor 对照 `templates` 的 references/运营/模板_联动更新清单.md 勾检通过。
- 任一同步项缺失，判定“需重改”，不得进入下一轮。
- 任一编码异常、字数/格式不达标，判定“需重改”。
