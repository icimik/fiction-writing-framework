# 质量检查清单

## A. 设定一致性

- [ ] 名称规范统一（机构/地名/平台/势力）
- [ ] 能力体系有代价与边界
- [ ] 时间线无矛盾
- [ ] 设定术语前后一致

## B. 角色与叙事

- [ ] 关键行为符合角色动机
- [ ] 无明显 OOC
- [ ] 视角切换清晰且可追踪
- [ ] 信息释放不倾倒

## C. 情节节奏

- [ ] 本章有明确推进目标
- [ ] 至少一个有效冲突
- [ ] 章末有钩子
- [ ] 伏笔新增和回收有记录

## D. 生产与运营

- [ ] 本章完成后更新工作日志
- [ ] 重要变更已登记到变更记录
- [ ] 反馈已归档并形成调整结论
- [ ] 周期复盘按计划执行
- [ ] 若样章已被采纳，已明确执行“直接转正”或“改写转正并归档”，未保留并行正文

## E. 变更纪律与交付规范

- [ ] 单次仅变更一个对象（章节/大纲/设定）
- [ ] 章节改写为整章重写，非局部替换或简单追加
- [ ] 未创建 `.bak` / `_old` 等正文副本
- [ ] 字数符合要求，格式符合章名与分节规范
- [ ] 风格、视角、节奏保持一致
- [ ] 生成后编码检查通过（无乱码/异常字符）
- [ ] 项目目录序号无冲突；发布目录使用 `10-publication/`
- [ ] 质量评审目录使用 `11-quality/`

## F. 多Agent协作验收

- [ ] 当前对象已完成 Reviewer + Reader + Editor 三方审阅，未越级切换对象
- [ ] 若当前对象为样章批次，已形成独立样章评审单并明确转正/归档裁决
- [ ] Reader 反馈基于至少 3 个角色卡生成，并已在汇总中标注
- [ ] Editor 已输出三段式结果（汇总反馈 -> 改稿指令 -> 验收结论）
- [ ] 若触发联动更新，Editor 已按 `模板_联动更新清单` 完成勾检
- [ ] 未通过项已回退到改稿环节，未进入下一章节/下一对象

## G. 证据与追溯

- [ ] Reviewer 问题项均可定位（位置、违反规则、修复建议、证据来源齐全）
- [ ] Editor 每条关键结论均附信息来源引用（路径 + 条目/段落）
- [ ] Editor 的 P0 项至少具备 2 个来源（Reviewer + Reader 各至少 1 条）
- [ ] 本轮结论与改动已同步记录到变更记录与工作日志，能追溯到章节/设定项

## H. 短篇小说集横向检查

- [ ] 单篇审阅之外，已完成整组篇章横向比对
- [ ] 开篇方式不存在明显模板化重复
- [ ] 章节结构不存在成组镜像（如相同第二章功能位、相同中段揭示位）
- [ ] 同地区篇章保持统一制度语义，但阅读入口与冲突承载方式有差异
- [ ] 已明确哪些篇目为正式章节、哪些仍为样稿或归档稿

## I. 同世界观导入融合检查

- [ ] 导入资产已归档到 `99-archive/import-YYYYMMDD/`
- [ ] 已完成导入资产清单与融合评估
- [ ] 每项导入资产均有处理结论（保留 / 改写并并入 / 拆分吸收 / 仅归档）
- [ ] 导入后已复核核心设定、命名规则、时间线、阵营职能一致性
- [ ] 导入影响已同步更新到 foundation / outline / rules / logs / change-log

## J. 整书中文表达精修检查

- [ ] 已先产出整书逐章审读提要，再进入正文精修
- [ ] 高风险长篇已补整书逐章详细内容总结，避免精修误伤结构
- [ ] 本轮精修只改表达，不改结构、因果、人物关系、时间顺序与章尾钩子
- [ ] 压缩名词式说法、罗列型断句、不自然口语、翻译腔比喻已做系统排查
- [ ] 解释腔、概念先行句、判词句、过满收束句已做回收
- [ ] 高风险章节已逐字句回读，并复核前后章节衔接
- [ ] 短信、便签、系统提示、药盒说明等文本载体的口径已按中文阅读习惯统一

## K. 终稿级多方评审与停改裁决检查

- [ ] 已对完整正文执行整书级 Reviewer 评审
- [ ] 已完成至少 3 份整书级 Reader 反馈
- [ ] Editor 已输出终稿汇总、改稿指令与裁决结论
- [ ] 终稿裁决已明确为“继续精修 / 通过 / 停止正文大修转发布”之一
- [ ] 若判定可发布，当前不存在 P0 / P1
- [ ] 若仍需回改，已明确具体章节、具体问题、具体影响，不因模糊不满意返工

## L. 发布准备与校样检查

- [ ] 发布阶段未重开结构性改稿
- [ ] 平台发布名、内部工作名、类型标签、简介版本已统一口径
- [ ] 推荐文案、平台文案、章节推广文案、作者手记、后记服从正文终稿气质
- [ ] 正文停改后，发布资产已作为一个资产包统一回看，未出现“正文已冷下来，外部文案仍沿用旧宣传腔”的温差
- [ ] 未将作品误包装为猎奇、悬疑、惨烈奇观或成功学逆袭
- [ ] 发布前最终核对单已完成
- [ ] 已从现有资产中选定默认平台页简介版本、首发最小组合与卷后材料节选策略，未临场重写
- [ ] 已形成发布前最终核验文档，明确文本层通过项与剩余投放动作
- [ ] 校样与版面处理只涉及分段、标点、载体适配和异常格式修正，不改变句意与事件结构

## M. 结项复盘与框架反哺检查

- [ ] 已对本项目的高频问题、流程新增点、硬规则和方法做系统复盘
- [ ] 新形成的流程资产已写回流程文档、检查清单或模板
- [ ] 结项结论不只停留在项目日志，已反哺框架层资产

## N. 风格与中文基线检查

- [ ] 长篇 / 连载 / 多 POV / 强风格约束项目已建立 `STYLEGUIDE.md`
- [ ] 持续复用的主要角色已建立对应 `SOUL.md`
- [ ] 若项目存在明确中文表达要求，已建立短引用的项目写作语言参考，并优先以上游 `framework/07-specifications/language/` 或项目专属材料为来源，未直接依赖过长原始材料
- [ ] `STYLEGUIDE.md`、`SOUL.md` 与项目写作语言参考均从设定、角色弧线、大纲与体裁形式推导，而不是从现有正文惯性反推
- [ ] 若这些文档是在已有正文基础上补建，已明确写出用途边界（继续生成基线 / 分析与最小修正基线），未借机重开结构
- [ ] 项目写作语言参考已把来源材料压成“高发问题 + 可执行工具”，而不只是概念摘录或目录搬运
- [ ] 生成、改写、复核前，已先读 `STYLEGUIDE.md`、对应 `SOUL.md` 与当前篇章裁决
- [ ] 终局或供词高风险章节，至少按“结构与证据 -> 声线与人设 -> 场面与中文 -> 终局专项”四轮顺序复核过
