# 模板_Editor汇总与改稿指令

## 使用说明

- 由 Editor 在每轮评审后输出。
- 必须先汇总 Reviewer 与 Reader 的输入，再下发 Writer 改稿指令。
- 每条结论必须给出信息来源引用（文档路径 + 章节/条目）。

## Editor汇总单

```markdown
# Editor汇总与改稿指令
- 轮次：第___轮
- 覆盖范围：第___章-第___章 / 设定版本___ / 大纲版本___
- 汇总时间：YYYY-MM-DD

## A. 输入来源（必须完整填写）
1. Reviewer评审单：
   - 文件：
   - 关键结论：
2. Reader反馈单（至少3个角色卡）：
   - 文件1：
   - 文件2：
   - 文件3：
3. Writer改动说明（如有）：
   - 文件：

## B. 共识与冲突
### 1) 共识问题（多来源一致）
- 问题：
- 影响：
- 信息来源：
  - [来源1] 路径 + 条目/段落
  - [来源2] 路径 + 条目/段落

### 2) 冲突问题（来源意见不一致）
- 冲突点：
- 裁决原则：
- 裁决结论：
- 信息来源：
  - [来源1] 路径 + 条目/段落
  - [来源2] 路径 + 条目/段落

## C. 改稿优先级（P0/P1/P2）
### P0（阻塞发布，必须先改）
1. 指令：
   - 目标：
   - 验收标准：
   - 信息来源：
     - [来源] 路径 + 条目/段落

### P1（显著影响阅读体验）
1. 指令：
   - 目标：
   - 验收标准：
   - 信息来源：
     - [来源] 路径 + 条目/段落

### P2（优化项）
1. 指令：
   - 目标：
   - 验收标准：
   - 信息来源：
     - [来源] 路径 + 条目/段落

## D. 联动更新要求（如触发）
- [ ] 已要求 Writer 执行 `模板_联动更新清单`
- 触发原因：章节新增 / 大纲改动 / 设定改动
- 信息来源：
  - [来源] 路径 + 条目/段落

## E. 验收结论
- 本轮结论：通过 / 需重改
- 下轮入口：继续创作 / 回到改稿 / 回到设定
- 信息来源：
  - [来源1] 路径 + 条目/段落
  - [来源2] 路径 + 条目/段落
```

## 来源引用规范（强制）

每条关键结论至少引用 1 个来源；P0 项至少引用 2 个来源（Reviewer + Reader 各至少 1 条）。

推荐写法：
- `framework/08-operations/feedback/Reader反馈_第12章_角色A.md#“节奏评价”`
- `framework/04-quality/章节质检_第12章.md#“情节一致性”`
- `framework/08-operations/change-log/变更记录_20260310.md#“第12章改动”`
