# 标准创作流程

说明：本文件是执行层唯一流程入口。`SKILL.md` 只保留入口、原则与导航；阶段细则、停改规则、终稿与发布流程以本文件为准。`多Agent操作流程.md` 是协作扩展说明，不单独定义主流程。方法细化原则必须使用 `framework/01-methods/rulebook/` 分册；现行硬规格查 `framework/07-specifications/`；`framework/references/` 仅用于原文追溯。

## 运行契约

角色分工：
- Writer：负责创作与改稿落地。
- Editor：负责编辑审阅、反馈汇总、改稿指令、停改裁决与阶段验收。
- Reviewer：负责规则化评审与质量打分。
- Reader：负责多读者画像反馈，包括单章体验、整书连读体验与渠道感知。

协作扩展：
- 角色交接、按阶段协作粒度、交接产物细则，见 `framework/02-process/多Agent操作流程.md`。

执行硬规则：
- 单次只允许变更一个对象：章节 / 大纲 / 设定（三选一）。
- 当任务切换为整书中文表达精修时，单个章节视为当前唯一对象，逐章推进。
- 当任务切换为整书终稿评审或发布准备时，整书终稿或发布资产包视为当前唯一对象。
- 单章节改写必须整章重写，不得以查找替换或末尾追加代替。
- 用户要求逐字逐句精修时，只允许重写句面，不得偷换结构、因果、人物关系与章尾钩子。
- 禁止创建 `.bak` 或同类正文副本。
- 每次生成后必须完成字数、格式、风格、视角、节奏、编码检查。
- 不用评论腔、议论文腔、概念化总结句代替小说句。
- 发布准备默认不重开结构性改稿。

运行模式：
- 通用创作模式：短中长篇、非日更、样章或全稿改写。
- 网文连载模式：日更/周更、市场验证与反馈循环强约束。
- 短篇小说集模式：多篇共享世界观、强调横向统一与纵向差异。

必填输入：
- 类型与题材
- 目标体量（字数或章数）
- 目标读者
- 创作目标（新建/续写/重写/审阅）
- 运行模式（通用创作/网文连载/短篇小说集）

缺省策略：
- 未给运行模式：默认通用创作。
- 未给章数：默认先交付“10 章节拍 + 1 章样章”。
- 未给风格：默认“清晰、叙事优先、展示驱动”。
- 未给创作目标：默认“新建”。
- 未给类型与题材：根据一句话设定关键词自动归类；若无法判定，默认“都市异能”。
- 未给目标读者：默认“18-35 岁网文读者，偏剧情驱动”。

单句启动兜底（仅提供一句话设定时）：
- 平台：默认“待定（按通用创作标准输出，可后置适配）”。
- 更新节奏：默认“每周 3 更”。
- 目标体量：默认“长篇，预计 120 章”。
- 禁用项：默认“无现实敏感映射、无超出设定边界的能力跳变”。

最小交付（MVP）：
- 一页式世界观（规则、限制、验证场景）
- 三角色卡（主角/对手/关键配角）+ 关系矩阵
- 10 章节拍大纲（每章推进目标 + 结尾钩子）
- 1 章样章（含自检要点）

## 标准执行链

1. 阶段 0：立项输入
2. 导入融合前置流程
3. 阶段 1：设定完善
4. 阶段 2：分析与规划
5. 阶段 3：样章验证
6. 阶段 4：反馈迭代
7. 阶段 5：持续生产
8. 阶段 6：周期复盘
9. 阶段 7：整书审读与中文表达精修
10. 阶段 8：终稿级多方评审与发布裁决
11. 阶段 9：发布准备 / 校样准备
12. 阶段 10：结项复盘与框架反哺

长篇项目补充要求：
- 阶段 7 不是普通语病修正，而是整书级表达系统校正。
- 阶段 8 默认以整书为对象，不再只看单章局部好坏。
- 阶段 9 默认不重开结构性改稿，只处理发布口径、校样和载体适配。
- 阶段 10 必须把本项目新形成的流程资产和规则资产回写框架。

## 阶段 0：立项输入

输入：idea 或基础设定文档。
输出：
- `00-intake/` 中保留 idea、原始设定与外部输入
- `01-brief/立项简报.md`

必填项：
- 类型与题材
- 目标读者
- 平台与更新节奏
- 目标体量
- 风格边界与禁用项

验证门槛：
- 是否能用一句话说明“主角-冲突-目标-代价”。
- 是否明确平台与更新约束。

必用方法分册：
- `framework/01-methods/rulebook/07.genre-overview.md`

网文连载附加动作：
- 先完成市场调研并形成《市场与竞品分析》初稿。
- 进行选题可行性验证：市场匹配度、差异化潜力、300+章可持续性。

短篇小说集附加动作：
- 明确是“单作者短篇集 / 设定集驱动短篇集 / 同世界观导入整编集”中的哪一种。
- 先定义短篇集统一内核：主题母题、制度母题、地区差异、篇幅带宽、篇章转正标准。

## 导入融合前置流程

适用：
- 存在外部创作空间的同世界观设定、短篇、长篇蓝图或历史稿。
- 需要在不打散核心设定的前提下，将外部资产并入当前项目。

输入：
- 外部导入文档、正文、设定、蓝图、时间线说明。

输出：
- `06-analysis-research/导入资产融合评估_*.md`
- `08-operations/feedback/导入融合审阅_*.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

建议模板：
- `framework/03-templates/模板_导入资产融合评估.md`

执行步骤：
1. 以批次归档导入源：
   - 存入 `99-archive/import-YYYYMMDD/`
   - 禁止直接把导入稿放进正式章节目录。
2. 建立资产清单：
   - 设定
   - 人物
   - 阵营
   - 时间线节点
   - 已完稿短篇
   - 蓝图/未写提纲
3. 做一致性体检：
   - 核心设定是否冲突
   - 时间线是否冲突
   - 命名规则是否冲突
   - 阵营职能是否冲突
   - 世界规则边界是否冲突
4. 对每项资产给出处理结论：
   - 保留
   - 改写并并入
   - 拆分吸收
   - 仅归档不转正
5. 统一落库：
   - 设定并入 `03-foundation/`
   - 可用大纲并入 `04-outline/`
   - 转正短篇并入 `07-writing/chapters/`
   - 未转正稿保留在归档层或 `07-writing/samples/`
6. 联动更新：
   - 角色
   - 世界观
   - 阵营
   - 时间线
   - 规则手册
   - 日志与变更记录

强制约束：
- 导入融合阶段优先级高于正文续写；未完成融合评估，不得将导入资产视为正式 canon。
- 若导入内容与当前项目冲突，优先保全当前项目核心设定，再决定重写导入稿。
- 导入融合允许整篇重写、角色替换、地区迁移、时间位置调整，但必须登记理由与影响范围。

## 阶段 1：设定完善

输入：立项简报。
输出：
- `03-foundation/世界观设定.md`
- `03-foundation/角色设定.md`
- `03-foundation/阵营设定.md`
- `05-rules/创作规则手册.md`
- 强风格约束项目补充：
  - `STYLEGUIDE.md`
  - `03-foundation/souls/*.SOUL.md`
  - `09-assets/项目写作语言参考_*.md`

执行要点：
- 能力体系必须写明限制、代价、弱点。
- 命名与映射规则必须先行（机构/地名/平台）。
- 设定文档需给出“开放问题”与后续回收计划。
- 架空处理优先，避免现实机构与地名直用。
- `STYLEGUIDE.md`、`SOUL.md` 与项目写作语言参考只允许从设定、角色弧线、分卷结构、题材与体裁形式推导，不得从现有正文惯性写法反推。
- 长篇、连载、多 POV 或用户对语言/人设稳定性有强要求的项目，必须在样章前补建项目级 `STYLEGUIDE.md`。
- 三个及以上会持续复用的主要角色，必须在样章前建立对应 `SOUL.md`，用于约束出场、行为、对白与关系判断。
- 若项目存在明显中文表达风险，或用户提供了教材、讲义、参考书等语言材料，必须优先参照 `framework/07-specifications/language/00.index.md` 及相关分册，再压缩成一个短引用的项目写作参考，让 `STYLEGUIDE.md` 引用；不得直接把过长原始材料作为高频执行入口。
- 若项目已经存在较多正文后才补建这些文档，必须先在文档定位中写明用途边界：
  - 继续生成的长期控制基线
  - 或发布阶段 / 审阅阶段的分析与最小修正基线
- 若为后者，不得把补建动作当作重开结构性改稿的授权。
- 若为短篇小说集，必须额外写明：
  - 地区命名规则
  - 时间线排序基准
  - 篇章转正标准
  - 跨篇角色复用规则
  - “规则约束核心设定，不约束篇章模板”的自由度边界

建议模板：
- `framework/03-templates/模板_STYLEGUIDE.md`
- `framework/03-templates/模板_SOUL.md`
- `framework/03-templates/模板_项目写作语言参考.md`

必用方法分册：
- `framework/01-methods/rulebook/01.worldbuilding.md`
- `framework/01-methods/rulebook/02.character.md`

## 阶段 2：分析与规划

输入：基础设定。
输出：
- `02-research/` 中沉淀原始调研材料、资料摘录与题材笔记
- `06-analysis-research/读者画像分析.md`
- `06-analysis-research/市场与竞品分析.md`
- `04-outline/分卷大纲.md`
- `04-outline/前三章节拍.md`

执行要点：
- `02-research/` 只放原始研究材料，不直接作为阶段结论出口。
- `06-analysis-research/` 只放已裁决、可执行的分析结论与策略文件。
- 先做读者画像，再定爽点/信息密度分布。
- 分卷大纲需包含：卷目标、小高潮、灵魂黑夜、卷末钩子。
- 章节规划必须明确：核心事件、人物出场、爽点类型、结尾钩子。
- 前三章节拍必须覆盖：世界观入口、主角动机、首个冲突闭环。
- 新项目必须由 Editor + Writer 联合完成选题分析（市场匹配、差异化、可持续性）。
- 若为短篇小说集，必须额外产出：
  - 短篇矩阵（地区 / 时间线 / 角色 / 母题 / 冲突入口）
  - 横向差异化检查（开篇方式 / 章节结构 / 信息释放方式）
  - 转正顺序与篇幅带宽规划

建议模板：
- `framework/03-templates/模板_短篇矩阵.md`
- `framework/03-templates/模板_篇章反雷同审阅单.md`

必用方法分册：
- `framework/01-methods/rulebook/03.plot.md`
- `framework/01-methods/rulebook/04.narrative.md`

## 阶段 3：样章验证

输入：分卷与节拍。
输出：
- `07-writing/samples/第1章.md`
- `07-writing/samples/第2章.md`
- `07-writing/samples/第3章.md`
- `08-operations/feedback/Reviewer评审单_样章_*.md`
- `08-operations/feedback/Reader反馈_样章_*.md`
- `08-operations/feedback/Editor汇总与改稿指令_样章_*.md`
- `11-quality/样章评审_*.md`

执行要点：
- 前三章必须完成：世界观入口、主角动机、首个冲突闭环。
- 样章阶段必须完成 Reviewer + Reader + Editor 三方审阅，再形成最终样章评审单。
- 样章评审必须给出可执行修改项，不只给结论。
- 若项目已建立 `STYLEGUIDE.md` 与 `SOUL.md`，则生成样章和执行样章审阅前必须先读：
  - `STYLEGUIDE.md`
  - 当前 POV 对应的 `SOUL.md`
  - 当前篇章节拍或最近一轮裁决
- 如有多个方向，允许并行生成多组三章样稿后择优。
- 样章被采纳时，必须在以下两种路径中二选一：
  - 直接转正：将样章文件从 `07-writing/samples/` 转移到 `07-writing/chapters/`，不保留并行正文副本。
  - 改写转正：正式版本写入 `07-writing/chapters/`，原样章及相关样章审阅文档归档到 `99-archive/samples-YYYYMMDD/`。
- 样章一旦转正，后续评审、精修和续写统一以 `07-writing/chapters/` 为唯一正文入口。
- 样章转正或归档动作必须同步更新变更记录与工作日志。

必用方法分册：
- `framework/01-methods/rulebook/05.rhetoric.md`
- `framework/01-methods/rulebook/06.editing-review.md`

## 阶段 4：反馈迭代

输入：作者/编辑/读者反馈。
输出：
- `08-operations/feedback/章节反馈_*.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

执行要点：
- 反馈按情节/角色/设定/节奏/文风分类。
- 每条调整都要标注“立即执行/延后执行/不采纳”。
- 需形成“问题-原因-动作-验证”闭环，不可只记录观点。
- Editor 必须汇总 Reviewer 评审单与 Reader 反馈单，输出改稿优先级（P0/P1/P2）。
- Reader 反馈必须基于 `framework/03-templates/模板_Reader读者角色卡.md` 至少 3 个角色卡执行。
- 若为短篇小说集，Editor 必须额外输出：
  - 单篇合规问题
  - 整组雷同问题
  - 转正/回退/归档建议

建议模板：
- `framework/03-templates/模板_篇章反雷同审阅单.md`

## 阶段 5：持续生产

输入：修订后的大纲与规则。
输出：
- `07-writing/chapters/第X章.md`
- `11-quality/章节质检_第X章.md`
- `08-operations/logs/工作日志_*.md`

执行要点：
- 每章完成后至少更新一次工作日志。
- 每 5-10 章检查一次伏笔台账与主线推进比例。
- 单章目标字数：3500-4500（可浮动 ±10%）。
- 项目规则可覆盖默认值：
  - 若项目定义为主线史诗/大长篇，可提升到 5500-6500。
  - 若项目要求逐章文件化，则每章单独保存为一个 Markdown 文件。
- 章节格式：
  - 长篇/连载：使用阿拉伯数字章名（`第X章`），不使用 hr 分割线。
  - 短篇小说集：允许使用 `地区·篇名` 或同等层级的篇名格式，但必须在项目规则中统一。
- 内容质量最低要求：
  - 情节一致性：不偏离分卷主线。
  - 人物一致性：动机与行为前后一致。
  - 专业细节：复杂概念需可读化表达。
- 若本轮有章节/大纲/设定改动，必须同步联动更新角色、世界观、阵营与日志（使用 `framework/03-templates/模板_联动更新清单.md`）。
- 章节改写必须整章重写并保持上下文连贯，不得做局部替换式修补。
- 生成完成后必须执行编码检查，确保无乱码与异常字符。

## 阶段 6：周期复盘

输出：

## 阶段 7：整书审读与中文表达精修

适用：
- 全书结构已稳定，但语言层仍存在翻译腔、英语痕迹、中文表达不顺、文本载体口径不统一等问题。
- 用户明确要求“逐章重表达”“逐字逐句精修”“按中文习惯重写句面”。

输入：
- 完整正文
- 既有大纲、设定、整书评审资产

输出：
- `11-quality/整书中文表达逐章审读提要_*.md`
- `11-quality/整书逐章详细内容总结_*.md`
- 分批精修后的 `07-writing/chapters/第X章.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

建议模板：
- `framework/03-templates/模板_整书中文表达审读提要.md`
- `framework/03-templates/模板_联动更新清单.md`

执行原则：
- 只改表达，不改结构。
- 只改句面，不偷换人物判断。
- 保留既有节奏、章尾钩子、因果链和信息释放顺序。
- 先整书读清，再逐章下刀，不做盲目局部替换。
- 若项目已建立 `STYLEGUIDE.md`、`SOUL.md` 或项目写作语言参考，则整书精修前必须先读这些文档，再读大纲与最近一轮评审裁决。
- 若整书精修暴露出的首要问题已从结构转为“语言漂移 / POV 同质化 / 角色功能化”，应先补建 `STYLEGUIDE.md` 与 `SOUL.md`，再继续精修。
- 若这些文档是在已有正文基础上补建，仍必须遵守“从设定 / 大纲 / 角色弧线 / 题材形式推导，再回头分析现稿”的顺序，不得直接从正文倒推一套新规则再反向压正文。

标准动作：
1. 先做逐章审读提要：
   - 每章写清“本章内容摘要”和“中文表达初判”。
   - 目的不是润色，而是防止精修误改叙事任务。
2. 对高风险长篇补逐章详细内容总结：
   - 防止中后段精修时丢失结构记忆。
3. 按批次执行整章表达重写：
   - 优先按卷、按章段、按风险批次推进。
   - 每一批都必须回读前后衔接。
4. 对高风险章节执行逐字句精修：
   - 终章、卷尾、制度说明密度高的章节优先。
5. 做整书回读与口径复核：
   - 复核首尾气质、关键物件、人物称谓、文本载体和整书语气。
6. 联动发布资产：
   - 若正文气质发生明显统一，发布文案、手记、后记也必须同步顺中文口径。

重点清理项：
- 压缩名词式说法。
- 罗列型断句。
- 不自然口语。
- 翻译腔比喻。
- 解释腔、分析腔、概念先行句。
- “不是因为……而是因为……”等过强逻辑骨架。
- 判词句、对照句、元叙事残留。
- 写得太满、太圆、太会说明自己的收束句。

文本载体细则：
- 短信、聊天、系统提示保留其载体感，不做一刀切书面化。
- 便签、标签、药盒说明、护士留言等短文本，按物理载体习惯处理，不强塞完整书面标点。
- 短引文可用“【】”，长段引文可用「」或分段处理，但必须服从正文阅读习惯。
- 标点位置服从中文排版常识，例如说明句末标点一般放在引示括号外。

## 阶段 8：终稿级多方评审与发布裁决

适用：
- 正文已完成整书级生产与主要精修，准备做发布前裁决。

输入：
- 终稿正文
- 阶段 7 精修资产
- 既有整书评审与反馈资产

输出：
- `11-quality/整书终稿评审_*.md`
- `08-operations/feedback/Reader反馈_*_整书终稿_角色*.md`
- `08-operations/feedback/Editor汇总与改稿指令_*_整书终稿轮.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

执行要求：
- Reviewer 以整书为单位评审，不再局限单章局部。
- Reader 至少 3 份，必须补充整书连读感受、章节间口径一致性、弃读风险位置与传播感知。
- Editor 必须明确给出以下三种裁决之一：
  - 继续精修
  - 通过
  - 停止正文大修，转入发布准备

裁决规则：
- 若存在 P0 或 P1，继续正文改稿。
- 若不存在 P0 / P1，且剩余问题主要是说明密度、措辞、校样、发布口径，则停止正文大修，转入阶段 9。
- 终稿结论必须同步更新日志和变更记录。

## 阶段 9：发布准备 / 校样准备

适用：
- 终稿裁决通过后，进入对外发布、排版适配和文案整理阶段。

输入：
- 终稿正文
- 阶段 8 裁决结果

输出：
- `10-publication/平台发布准备_*.md`
- `10-publication/推荐文案包_*.md`
- `10-publication/微博发布文案包_*.md`
- `10-publication/小红书发布文案包_*.md`
- `10-publication/抖音发布文案包_*.md`
- `10-publication/章节社交推广文案_*.md`
- `10-publication/作者手记_*.md`
- `10-publication/后记_*.md`
- `10-publication/发布前最终核对单_*.md`
- `11-quality/发布前最终核验_*.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

建议模板：
- `framework/03-templates/模板_发布前最终核对单.md`
- `framework/03-templates/模板_发布前最终核验.md`
- `framework/03-templates/模板_Editor汇总与改稿指令.md`

执行边界：
- 不重开结构性改稿。
- 不补新事件改变人物命运。
- 不为了“更完整”补翻身、和解或说明性尾声。
- 只做发布口径统一、载体适配、版心适配、分段优化、异常标点修正、平台文案整理。

发布资产要求：
- 对外书名、平台标签、简介版本必须统一。
- 若内部工作名与对外发布名并存，必须明确边界，不混入平台页正文。
- 推荐文案、推广文案、手记、后记必须服从正文终稿气质，不退回概念化、宣传腔或翻译腔。
- 正文停改后，发布资产必须视为一个统一资产包做口径对齐，不允许各文件各自沿用旧温度。
- 在进入实际上传前，必须先从现有资产中选定：
  - 一个平台页简介版本
  - 一组首发最小组合
  - 一份卷后材料节选策略
- 默认从现有资产拷定，不临场重写。
- 发布前最终核对单完成后，应再形成一份“发布前最终核验”文档，明确：
  - 已通过的文本层结论
  - 仍待实际上传时完成的投放层动作
  - 默认首发最小组合

## 阶段 10：结项复盘与框架反哺

适用：
- 完整项目进入发布前或发布后收口阶段。

输出：
- `08-operations/retrospectives/结项复盘_*.md`
- 需要时更新框架文档、模板、检查清单、规则库与变更记录

执行要点：
- 复盘目标不是总结辛苦，而是提炼：
  - 本项目遇到的高频问题
  - 新增的流程节点
  - 新形成的硬规则
  - 可复用的方法与停改判断线
- 框架反哺必须写回框架文档，而不是只留在项目日志里。
- 若项目验证出 `STYLEGUIDE / SOUL / 项目写作语言参考 / 发布最终核验` 的新边界或新链路，必须优先回写流程、模板和检查清单，而不是只在项目内保留特例说明。

## 正文停改与发布收口规则

进入“停止正文大修，转入发布收口”的条件：
1. 整书主线、人物关系、因果链、卷尾接力已经稳定。
2. 整书终稿评审不存在 P0 / P1。
3. 剩余问题主要落在说明密度、措辞口径、排版校样、发布文案统一。
4. Editor 明确给出“通过”或“可进入发布准备收口阶段”的结论。

进入发布状态后允许做的事：
- 轻量校样。
- 长段分段与版面适配。
- 文本载体口径统一。
- 发布页简介与社交文案整理。
- 作者手记、后记与附言整理。

进入发布状态后默认不做的事：
- 不重开结构性改稿。
- 不补新事件改变人物命运。
- 不把正文终稿重新拉回逐章大修。

若确有例外，必须满足：
- 有明确 P0 / P1 证据。
- 能指出具体章节、具体问题和具体影响。
- Editor 重新裁定后再开正文改稿，不得凭模糊不满意反复返工。

## 既有项目接入模式

适用：已有文稿、设定、历史目录杂乱项目。

执行步骤：
1. 按 `framework/02-process/项目结构模板.md` 重组目录与资产。
2. 将既有设定归档到 `03-foundation/`，既有正文归档到 `07-writing/chapters/`。
3. 由 Reviewer 先做基线体检，Editor 生成修复清单。
4. Writer 按修复清单完成首轮改稿，再进入标准阶段 4-10 循环。

## 同世界观导入整编模式

适用：
- 当前项目已运行，后续又接收到来自其他创作空间的同世界观稿件或设定。

执行步骤：
1. 新建导入批次目录：`99-archive/import-YYYYMMDD/`
2. 完成 `导入资产融合评估_*.md`
3. 逐项裁决导入资产的 canon 状态与处理动作
4. 先更新 foundation / outline / rules，再处理正文
5. 对受影响篇章执行基线复审与反雷同复审
6. 记录批次影响范围与后续待改篇目

## 周期机制

日常循环（每日触发）：
1. 读取当前进度与对应章节节拍。
2. 生成下一章。
3. 执行自动质检（连贯性、逻辑、文风）。
4. 问题修正后落盘并更新日志。

每周复盘（建议周日）：
1. 检查更新达成率、字数达标率、质检问题分布。
2. 汇总读者与编辑反馈关键词。
3. 输出下周策略调整。

每月复盘：
1. 分析读者偏好与市场风向变化。
2. 评估作品差异化与长期可持续性。
3. 决策是否进行中期方向调整。

章节数触发复盘：
- 每 7 章：输出阶段分析，重点看短弧完成度、爽点密度、节奏拖沓风险。
- 每 30 章：输出分卷分析，重点看卷结构完整性、人物弧光、世界观揭示节奏。
- 整书完成后：强制进入阶段 7 和阶段 8，不得直接跳到发布。

## 质量门槛（Rubric）

评分维度（5 分制）：
1. 规则一致性
2. 角色驱动性
3. 情节因果性
4. 叙事有效性
5. 语言可读性

建议阈值：
- 通用创作：平均分 > 4.1
- 网文连载：平均分 > 4.1，且章节钩子强度 > 4.3
- 终稿发布判断：默认无 P0 / P1，且 Editor 裁决通过后方可进入阶段 9

补充说明：
- Rubric 的 5 个基础维度适用于所有模式。
- `章节钩子强度` 是网文连载模式的附加指标，不计入 5 项基础维度数量，但必须单独记录并用于是否过线的判断。

## 反馈闭环（结构化处理）

1. 收集与分类：按情节/人物/文风/专业度/节奏归档。
2. 优先级排序：按紧急度、普遍性、改动成本排序。
3. 生成调整方案：标注立即执行、分批优化、待决策项。
4. 验证与沉淀：对比调整前后反馈，更新规则与清单。
5. 整书结项后：将新增流程与规则回写框架。

## 异常处理

1. 连续偏离大纲：暂停生成，先回到分卷目标重建节拍。
2. 读者负反馈激增：触发紧急复盘并压缩试错窗口。
3. 文风或质量下滑：强制执行样章级重审再恢复日更。
4. 中文表达精修中误伤结构：立即回到该章审读提要，按“叙事任务优先”回修。
5. 发布阶段出现“还想再大修正文”的冲动：先对照“正文停改与发布收口规则”裁决，不凭模糊不满意返工。
