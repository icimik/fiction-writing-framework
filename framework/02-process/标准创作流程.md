# 标准创作流程

说明：本文件是执行层唯一流程入口。方法细化原则必须使用 `framework/01-methods/rulebook/` 分册；`framework/references/` 仅用于原文追溯。

## 运行契约

角色分工：
- Writer：负责创作与改稿落地。
- Editor：负责编辑审阅、反馈汇总、改稿指令与验收。
- Reviewer：负责规则化评审与质量打分。
- Reader：负责多读者画像反馈（男频/女频/轻小说/现实向等）。

执行硬规则：
- 单次只允许变更一个对象：章节 / 大纲 / 设定（三选一）。
- 单章节改写必须整章重写，不得以查找替换或末尾追加代替。
- 禁止创建 `.bak` 或同类正文副本。
- 每次生成后必须完成字数、格式、风格、视角、节奏、编码检查。

运行模式：
- 通用创作模式：短中长篇、非日更、样章或全稿改写。
- 网文连载模式：日更/周更、市场验证与反馈循环强约束。
- 短篇小说集模式：多篇共享世界观、强调横向统一与纵向差异。

必填输入：
- 类型与题材
- 目标体量（字数或章数）
- 目标读者
- 创作目标（新建/续写/重写/审阅）
- 运行模式（通用创作/网文连载/短篇小说集）

缺省策略：
- 未给运行模式：默认通用创作。
- 未给章数：默认先交付“10 章节拍 + 1 章样章”。
- 未给风格：默认“清晰、叙事优先、展示驱动”。
- 未给创作目标：默认“新建”。
- 未给类型与题材：根据一句话设定关键词自动归类；若无法判定，默认“都市异能”。
- 未给目标读者：默认“18-35 岁网文读者，偏剧情驱动”。

单句启动兜底（仅提供一句话设定时）：
- 平台：默认“待定（按通用创作标准输出，可后置适配）”。
- 更新节奏：默认“每周 3 更”。
- 目标体量：默认“长篇，预计 120 章”。
- 禁用项：默认“无现实敏感映射、无超出设定边界的能力跳变”。

最小交付（MVP）：
- 一页式世界观（规则、限制、验证场景）
- 三角色卡（主角/对手/关键配角）+ 关系矩阵
- 10 章节拍大纲（每章推进目标 + 结尾钩子）
- 1 章样章（含自检要点）

## 阶段 0：立项输入

输入：idea 或基础设定文档。
输出：`00-intake/立项简报.md`。

必填项：
- 类型与题材
- 目标读者
- 平台与更新节奏
- 目标体量
- 风格边界与禁用项

验证门槛：
- 是否能用一句话说明“主角-冲突-目标-代价”。
- 是否明确平台与更新约束。

必用方法分册：
- `framework/01-methods/rulebook/07.genre-overview.md`

网文连载附加动作：
- 先完成市场调研并形成《市场与竞品分析》初稿。
- 进行选题可行性验证：市场匹配度、差异化潜力、300+章可持续性。

短篇小说集附加动作：
- 明确是“单作者短篇集 / 设定集驱动短篇集 / 同世界观导入整编集”中的哪一种。
- 先定义短篇集统一内核：主题母题、制度母题、地区差异、篇幅带宽、篇章转正标准。

## 导入融合前置流程

适用：
- 存在外部创作空间的同世界观设定、短篇、长篇蓝图或历史稿。
- 需要在不打散核心设定的前提下，将外部资产并入当前项目。

输入：
- 外部导入文档、正文、设定、蓝图、时间线说明。

输出：
- `06-analysis-research/导入资产融合评估_*.md`
- `08-operations/feedback/导入融合审阅_*.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

建议模板：
- `framework/03-templates/模板_导入资产融合评估.md`

执行步骤：
1. 以批次归档导入源：
   - 存入 `99-archive/import-YYYYMMDD/`
   - 禁止直接把导入稿放进正式章节目录。
2. 建立资产清单：
   - 设定
   - 人物
   - 阵营
   - 时间线节点
   - 已完稿短篇
   - 蓝图/未写提纲
3. 做一致性体检：
   - 核心设定是否冲突
   - 时间线是否冲突
   - 命名规则是否冲突
   - 阵营职能是否冲突
   - 世界规则边界是否冲突
4. 对每项资产给出处理结论：
   - 保留
   - 改写并并入
   - 拆分吸收
   - 仅归档不转正
5. 统一落库：
   - 设定并入 `03-foundation/`
   - 可用大纲并入 `04-outline/`
   - 转正短篇并入 `07-writing/chapters/`
   - 未转正稿保留在归档层或 `07-writing/samples/`
6. 联动更新：
   - 角色
   - 世界观
   - 阵营
   - 时间线
   - 规则手册
   - 日志与变更记录

强制约束：
- 导入融合阶段优先级高于正文续写；未完成融合评估，不得将导入资产视为正式 canon。
- 若导入内容与当前项目冲突，优先保全当前项目核心设定，再决定重写导入稿。
- 导入融合允许整篇重写、角色替换、地区迁移、时间位置调整，但必须登记理由与影响范围。

## 阶段 1：设定完善

输入：立项简报。
输出：
- `03-foundation/世界观设定.md`
- `03-foundation/角色设定.md`
- `03-foundation/阵营设定.md`
- `05-rules/创作规则手册.md`

执行要点：
- 能力体系必须写明限制、代价、弱点。
- 命名与映射规则必须先行（机构/地名/平台）。
- 设定文档需给出“开放问题”与后续回收计划。
- 架空处理优先，避免现实机构与地名直用。
- 若为短篇小说集，必须额外写明：
  - 地区命名规则
  - 时间线排序基准
  - 篇章转正标准
  - 跨篇角色复用规则
  - “规则约束核心设定，不约束篇章模板”的自由度边界

必用方法分册：
- `framework/01-methods/rulebook/01.worldbuilding.md`
- `framework/01-methods/rulebook/02.character.md`

## 阶段 2：分析与规划

输入：基础设定。
输出：
- `06-analysis-research/读者画像分析.md`
- `06-analysis-research/市场与竞品分析.md`
- `04-outline/分卷大纲.md`
- `04-outline/前三章节拍.md`

执行要点：
- 先做读者画像，再定爽点/信息密度分布。
- 分卷大纲需包含：卷目标、小高潮、灵魂黑夜、卷末钩子。
- 章节规划必须明确：核心事件、人物出场、爽点类型、结尾钩子。
- 前三章节拍必须覆盖：世界观入口、主角动机、首个冲突闭环。
- 新项目必须由 Editor + Writer 联合完成选题分析（市场匹配、差异化、可持续性）。
- 若为短篇小说集，必须额外产出：
  - 短篇矩阵（地区 / 时间线 / 角色 / 母题 / 冲突入口）
  - 横向差异化检查（开篇方式 / 章节结构 / 信息释放方式）
  - 转正顺序与篇幅带宽规划

建议模板：
- `framework/03-templates/模板_短篇矩阵.md`
- `framework/03-templates/模板_篇章反雷同审阅单.md`

必用方法分册：
- `framework/01-methods/rulebook/03.plot.md`
- `framework/01-methods/rulebook/04.narrative.md`

## 阶段 3：样章验证

输入：分卷与节拍。
输出：
- `07-writing/samples/第1章.md`
- `07-writing/samples/第2章.md`
- `07-writing/samples/第3章.md`
- `04-quality/样章评审.md`

执行要点：
- 前三章必须完成：世界观入口、主角动机、首个冲突闭环。
- 样章评审必须给出可执行修改项，不只给结论。
- 如有多个方向，允许并行生成多组三章样稿后择优。

必用方法分册：
- `framework/01-methods/rulebook/05.rhetoric.md`
- `framework/01-methods/rulebook/06.editing-review.md`

## 阶段 4：反馈迭代

输入：作者/编辑/读者反馈。
输出：
- `08-operations/feedback/章节反馈_*.md`
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

执行要点：
- 反馈按情节/角色/设定/节奏/文风分类。
- 每条调整都要标注“立即执行/延后执行/不采纳”。
- 需形成“问题-原因-动作-验证”闭环，不可只记录观点。
- Editor 必须汇总 Reviewer 评审单与 Reader 反馈单，输出改稿优先级（P0/P1/P2）。
- Reader 反馈必须基于 `framework/03-templates/模板_Reader读者角色卡.md` 至少 3 个角色卡执行。
- 若为短篇小说集，Editor 必须额外输出：
  - 单篇合规问题
  - 整组雷同问题
  - 转正/回退/归档建议

建议模板：
- `framework/03-templates/模板_篇章反雷同审阅单.md`

## 阶段 5：持续生产

输入：修订后的大纲与规则。
输出：
- `07-writing/chapters/第X章.md`
- `04-quality/章节质检_第X章.md`
- `08-operations/logs/工作日志_*.md`

执行要点：
- 每章完成后至少更新一次工作日志。
- 每 5-10 章检查一次伏笔台账与主线推进比例。
- 单章目标字数：3500-4500（可浮动 ±10%）。
- 项目规则可覆盖默认值：
  - 若项目定义为主线史诗/大长篇，可提升到 5500-6500。
  - 若项目要求逐章文件化，则每章单独保存为一个 Markdown 文件。
- 章节格式：
  - 长篇/连载：使用阿拉伯数字章名（`第X章`），不使用 hr 分割线。
  - 短篇小说集：允许使用 `地区·篇名` 或同等层级的篇名格式，但必须在项目规则中统一。
- 内容质量最低要求：
	- 情节一致性：不偏离分卷主线。
	- 人物一致性：动机与行为前后一致。
	- 专业细节：复杂概念需可读化表达。
- 若本轮有章节/大纲/设定改动，必须同步联动更新角色、世界观、阵营与日志（使用 `framework/03-templates/模板_联动更新清单.md`）。
- 章节改写必须整章重写并保持上下文连贯，不得做局部替换式修补。
- 生成完成后必须执行编码检查，确保无乱码与异常字符。

## 阶段 6：周期复盘

输出：
- `08-operations/retrospectives/周复盘_*.md`
- `08-operations/retrospectives/月复盘_*.md`
- `08-operations/retrospectives/N章复盘_*.md`
- `08-operations/retrospectives/分卷复盘_*.md`

执行要点：
- 周复盘看执行稳定性。
- 月复盘看策略方向。
- N章复盘看节奏偏移。
- 分卷复盘看结构完整性与商业性。
- 周期复盘由 Editor 与 Writer 协同主持，Reviewer 与 Reader 提供专项输入。

## 既有项目接入模式

适用：已有文稿、设定、历史目录杂乱项目。

执行步骤：
1. 按 `framework/02-process/项目结构模板.md` 重组目录与资产。
2. 将既有设定归档到 `03-foundation/`，既有正文归档到 `07-writing/chapters/`。
3. 由 Reviewer 先做基线体检，Editor 生成修复清单。
4. Writer 按修复清单完成首轮改稿，再进入标准阶段 4-6 循环。

## 同世界观导入整编模式

适用：
- 当前项目已运行，后续又接收到来自其他创作空间的同世界观稿件或设定。

执行步骤：
1. 新建导入批次目录：`99-archive/import-YYYYMMDD/`
2. 完成 `导入资产融合评估_*.md`
3. 逐项裁决导入资产的 canon 状态与处理动作
4. 先更新 foundation / outline / rules，再处理正文
5. 对受影响篇章执行基线复审与反雷同复审
6. 记录批次影响范围与后续待改篇目

## 周期机制

日常循环（每日触发）：
1. 读取当前进度与对应章节节拍。
2. 生成下一章。
3. 执行自动质检（连贯性、逻辑、文风）。
4. 问题修正后落盘并更新日志。

每周复盘（建议周日）：
1. 检查更新达成率、字数达标率、质检问题分布。
2. 汇总读者与编辑反馈关键词。
3. 输出下周策略调整。

每月复盘：
1. 分析读者偏好与市场风向变化。
2. 评估作品差异化与长期可持续性。
3. 决策是否进行中期方向调整。

章节数触发复盘：
- 每 7 章：输出阶段分析，重点看短弧完成度、爽点密度、节奏拖沓风险。
- 每 30 章：输出分卷分析，重点看卷结构完整性、人物弧光、世界观揭示节奏。

## 质量门槛（Rubric）

评分维度（5分制）：
1. 规则一致性
2. 角色驱动性
3. 情节因果性
4. 叙事有效性
5. 语言可读性

建议阈值：
- 通用创作：平均分 >= 3.5
- 网文连载：平均分 >= 3.5，且章节钩子强度 >= 4

## 反馈闭环（结构化处理）

1. 收集与分类：按情节/人物/文风/专业度/节奏归档。
2. 优先级排序：按紧急度、普遍性、改动成本排序。
3. 生成调整方案：标注立即执行、分批优化、待决策项。
4. 验证与沉淀：对比调整前后反馈，更新规则与清单。

## 异常处理

1. 连续偏离大纲：暂停生成，先回到分卷目标重建节拍。
2. 读者负反馈激增：触发紧急复盘并压缩试错窗口。
3. 文风或质量下滑：强制执行样章级重审再恢复日更。
