# 多Agent操作流程

## 目标

定义 Writer、Editor、Reviewer、Reader 的标准职责、交接产物与迭代节奏，确保多角色协同稳定运行。

## 角色职责与交接

1. Writer（创作）
- 输入：Editor 改稿指令、当前大纲、规则手册。
- 输出：章节草稿/改稿稿、改动说明。
- 交接给 Reviewer 与 Reader。

2. Reviewer（规则评审）
- 输入：Writer 当轮稿件、`framework/04-checklists/质量检查清单.md`、Rulebook 分册。
- 输出：规则评审单（评分、问题清单、严重级别、证据位置）。
- 交接给 Editor。

3. Reader（读者反馈）
- 输入：Writer 当轮稿件、`framework/03-templates/模板_Reader读者角色卡.md`。
- 输出：读者体验反馈单（爽点、拖沓点、代入感、弃读风险、推荐改动）。
- 交接给 Editor。

4. Editor（汇总与验收）
- 输入：Reviewer 评审单 + Reader 反馈单 + Writer 改动说明。
- 输出：
  - 汇总反馈（冲突点与共识点）
  - 改稿优先级（P0/P1/P2）
  - Writer 改稿指令
  - 验收结论（通过/需重改）
- 交接给 Writer 并进入下一轮。

## 标准协作循环

1. Writer 产出当轮稿件。
2. Reviewer 生成规则评审单。
3. Reader 按角色模板生成读者反馈单。
4. Editor 汇总并下发改稿指令。
5. Writer 改稿并提交联动更新记录。
6. Editor 验收通过后进入下一章节；未通过回到第4步。

执行约束：
- 每轮仅处理一个变更对象（章节/大纲/设定）。
- 当前对象未通过三方审阅（Reviewer + Reader + Editor）前，不得切换对象。
- 章节改写需整章重写，不得以局部替换或追加补丁代替。
- 禁止生成 `.bak`、`_old` 等正文副本。

## 新项目选题协同（Editor + Writer）

1. 收集候选题材与一句话设定。
2. 评估市场匹配度（热度、竞争、题材窗口）。
3. 评估差异化（卖点、叙事钩子、角色关系优势）。
4. 评估可持续性（100+章节冲突燃料、角色成长空间、世界扩展性）。
5. 输出《选题分析与立项建议》。

## 既有项目接入协同

1. Writer 先归档与重组既有资产（设定、正文、大纲）。
2. Reviewer 执行基线体检（设定一致性、人物连续性、主线完整性）。
3. Editor 输出修复清单与改写优先级。
4. Writer 完成首轮修复后进入标准协作循环。

## 强制联动更新（Writer 执行，Editor 验收）

触发条件：当轮发生以下任一改动：
- 新增章节
- 修改大纲
- 修改设定

必须同步更新：
- `03-foundation/角色设定.md`（角色清单/状态）
- `03-foundation/世界观设定.md`（规则与边界）
- `03-foundation/阵营设定.md`（阵营关系与利益）
- `08-operations/change-log/变更记录_*.md`
- `08-operations/logs/工作日志_*.md`

验收标准：
- Editor 对照 `framework/03-templates/模板_联动更新清单.md` 勾检通过。
- 任一同步项缺失，判定“需重改”，不得进入下一轮。
- 任一编码异常、字数/格式不达标，判定“需重改”。
