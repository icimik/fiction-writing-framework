# 项目标准模板（Project Template）

每个项目统一采用以下目录结构：

```text
项目名/
  README.md                    # 项目入口文件
  STYLEGUIDE.md               # 项目级风格总纲（长篇 / 连载 / 强风格约束项目推荐）
  00-intake/                  # 输入与立项来源（idea/设定原稿）
  01-brief/                   # 创作简报、边界与目标
  02-research/                # 市场、竞品、题材调研
  03-foundation/              # 世界观、角色、阵营等基础设定
    souls/                    # 主要角色灵魂档案（角色连续性要求高的项目推荐）
  04-outline/                 # 分卷大纲、章节节拍
  05-rules/                   # 项目专属创作规则与复用规则映射
  06-analysis-research/       # 读者画像、定位分析、策略分析
  07-writing/
    samples/                  # 前三章样稿
    chapters/                 # 正式章节
  08-operations/
    logs/                     # 工作日志/创作手记
    feedback/                 # 作者/读者/编辑反馈汇总
    retrospectives/           # 周/月/N章/分卷复盘
    change-log/               # 变更记录
  09-assets/                  # 插图、设定图、附加资源
  10-publication/             # 发布准备、平台文案、后记、作者手记、校样核对
  11-quality/                 # 样章评审、章节质检、整书评审、终稿评审、表达精修资产
  99-archive/                 # 项目内部历史归档
    samples-YYYYMMDD/         # 样章转正或改写转正后的历史归档批次
    import-YYYYMMDD/          # 同世界观外部导入批次（按日期追溯）
```

## 编号规则

- 一级目录使用两位数字前缀保持顺序。
- 同一项目内目录序号不得冲突。
- 发布准备目录统一使用 `10-publication/`。
- 质量评审目录统一使用 `11-quality/`。
- 项目入口文件统一使用根目录 `README.md`。

## 项目入口文件

- 每个项目都应在根目录提供 `README.md`。
- 该文件不是框架全文副本，而是项目级入口说明，至少回答：
  - 当前项目目录如何对应框架模板
  - 当前项目处于哪个阶段
  - 哪些文档是当前真实入口
  - 当前下一步要做什么
- 推荐模板：`framework/03-templates/模板_项目README.md`

## 统一执行流程

1. 在根目录创建 `README.md`，写清当前目录、当前阶段和下一步动作。
2. 在 `00-intake/` 放入 idea 或初始设定。
3. 在 `01-brief/` 明确受众、平台、体量、更新节奏。
4. 在 `03-foundation/` 完善世界观、角色、阵营。
5. 长篇、连载或强风格约束项目，在样章前建立 `STYLEGUIDE.md`；主要角色写入 `03-foundation/souls/`。
6. 若项目有明确中文表达约束，在 `09-assets/` 建立短引用的项目写作语言参考；其上游应优先引用 `framework/07-specifications/language/` 的核心规格，再补项目专属材料。
7. 在 `05-rules/` 建立项目规则（并引用复用规则）。
8. 在 `06-analysis-research/` 完成读者画像与市场匹配分析。
9. 在 `04-outline/` 完成分卷大纲与前三章节拍。
10. 在 `07-writing/samples/` 产出前三章样稿，完成 Reviewer + Reader + Editor 三方审阅，并形成样章评审单。
11. 样章被采纳后，按转正规则进入 `07-writing/chapters/`。
12. 在 `08-operations/feedback/` 汇总反馈并生成调整动作。
13. 后续章节在 `07-writing/chapters/` 持续生产。
14. 发布准备资产统一进入 `10-publication/`。
15. 质量评审、章节质检、整书终稿评审资产统一进入 `11-quality/`。
16. 全程记录 `08-operations/logs/`，并按周期写复盘。

## 样章转正与归档规则

适用：前三章样稿或其他作为试写样章的章节。

1. 直接采纳为正式章节
- 若样章内容被采纳，样章文件应从 `07-writing/samples/` 转移到 `07-writing/chapters/`。
- 转移后，`samples/` 不再保留同名副本，避免并行正文。
- 样章评审文档和反馈文档可继续保留在原质量/反馈目录，作为正式章节的前置审阅资产。

2. 改写为正式章节
- 若样章只是提供基础，但需要重写后才转正，则正式版本写入 `07-writing/chapters/`。
- 原样章正文及其相关样章审阅文档统一归档到 `99-archive/samples-YYYYMMDD/`。
- 归档后，后续只以 `chapters/` 中的正式章节继续生产、评审和精修。

3. 通用要求
- 样章转正或归档动作必须写入变更记录与工作日志。
- `07-writing/samples/` 只保留未转正或待裁决样稿。
- `07-writing/chapters/` 只保留当前正式正文。

## 短篇小说集补充结构

适用：设定集驱动短篇集、同世界观多地区短篇集。

建议补充：
- `04-outline/短篇矩阵_*.md`
- `04-outline/短篇扩展大纲_*.md`
- `06-analysis-research/篇章反雷同审阅与改稿清单_*.md`
- `06-analysis-research/导入资产融合评估_*.md`
- `11-quality/`
- `08-operations/feedback/reviews-YYYYMMDD/`

执行原则：
- `07-writing/samples/` 保留未转正样稿。
- `07-writing/chapters/` 只放已转正的正式篇章。
- 导入短篇在完成融合评估前，一律先放 `99-archive/import-YYYYMMDD/`。
